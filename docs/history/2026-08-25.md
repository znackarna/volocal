### 2026-08-25 — Parked: the page in two languages, and how it would be built

The owner asked whether a language switch belonged in the footer, believing the
site already chose a language by itself. It does not — **the site is Czech
only.** `<html lang="cs">`, one HTML file, and not a line about language in any
of its three scripts. A switch would have had nothing to switch to.

What does choose automatically is the **application**: `detectedLanguage()` in
`src/i18n.tsx` reads a saved choice out of `localStorage` first and only then
looks at `navigator.languages` for `cs`. Settings can change it and it is
remembered, so automatic is the first-run default there, not the only option.
Nothing to add.

#### What an English page actually costs

Measured rather than guessed — 1 600 words of visible text on the page, and
they split very unevenly:

| | words | where the English comes from |
|---|---|---|
| inside the application mock-ups (6 carousel slides, 10 reveal cards) | **915** | **already exists**, `src/locales/en/` |
| the page's own copy (headline, ledes, cards, FAQ, steps, footer) | **685** | has to be written |

The 915 are not translated, they are **taken**: twelve strings sampled from the
windows and eleven have an English twin in the dictionaries already — *Mluvčí →
Speakers*, *Uložit → Save*, *AI nástroje → AI tools*, *Kontrola → Review*,
*Odepnout → Unpin*. The Czech page quotes the Czech application; the English one
would quote the English application, and could not then claim something the
program does not say.

So the real cost is 685 words in the owner's English voice.

#### His idea, and why it is right one step earlier

He asked whether the page could load its translations from JSON — one page,
strings from outside, translation made easy.

**Not in the browser.** The bots that build link previews and search results
mostly do not run JavaScript; they would get an empty shell. And `description`
and the `og:` tags cannot be swapped by script for a crawler at all — it reads
the HTML it was handed and is gone. It would undo both things repaired this
morning, and a reader with no JavaScript would get a blank page.

**At build time, yes, and it is the better shape:**

```
docs/site/copy.cs.json     translation happens here
docs/site/copy.en.json
docs/site/index.html       template, keys instead of text
        -> the workflow renders /  and  /en/
```

Plain static HTML goes out, with the text in it, each language carrying its own
`description`, `og:` and `hreflang`. A translator never opens the HTML. Three
things fall out of it for free: the mock-ups can read `src/locales/` directly
instead of holding a copy; agreement between the two languages becomes a
comparison of key sets, so a missing translation fails the build rather than
letting the halves drift for six months; and the repository already has the
pattern in `scripts/i18n.mjs` (`check`, `sync`, `export`, `import`).

**What it costs, since this entry exists so nobody has to rediscover it:**
`index.html` loses its text and gains keys, so reading it stops being reading
the page. And a build appears where there is none today — the workflow copies a
folder and nothing else — which is one more thing that can go wrong between a
commit and the live page.

The suggested order, if it happens: mechanism first with Czech alone, proving
it renders byte for byte what is served today, and English only after. That
separates *we rebuilt it* from *we translated it*.

**Parked on 25 August at the owner's word — he wants to talk it over with a
colleague first.** Nothing has been built. This entry is the briefing.

### 2026-08-25 — A menu for the phone, with room for what goes into it later

Asked for by the owner, who also said what it is for beyond today: the theme
switch and, when there is one, the language switch belong in it.

From 620 px down — the page's own phone breakpoint, so no new number enters the
stylesheet — the two quiet links go behind a button. *Stáhnout* stays in the
header: the rule above it in the stylesheet has said since the page was written
that of the three places to go only one is what the page is for, and hiding the
one thing a visitor came to do inside a menu would contradict it.

#### The panel is the nav, not a copy of it

`.top-nav` is the same element in both states — a row in the header above the
breakpoint, a card under the button below it. There is one list of places to go
and no way for a phone and a desktop to disagree about what is on it, which is
the failure a second copy of the links would have introduced on the day someone
adds a third link.

#### It collapses only when the script says so

`has-menu` is added by JavaScript rather than written into the markup. With no
script the links stay in the header exactly as they are today: a phone with no
JavaScript gets a crowded header instead of a page with no navigation, which is
the right way round. Everything the collapse does hangs off that one class.

What the script gives it beyond opening and shutting: Escape closes it and puts
focus back on the button, a pointer landing anywhere else closes it, following a
link closes it — `#firmy` scrolls the page underneath, and a panel still
standing over the place it just took you to is a panel nobody asked to keep —
and crossing the breakpoint while it is open puts the links back in the header
rather than leaving a hidden `<nav>` behind.

#### Measured at seven widths

1280, 900, 621, 620, 480, 390 and 320 px. The button appears at 620 and not at
621. No sideways scroll at any width, open or shut. The panel lands inside the
viewport at every one of them, including 320, where its right edge sits on the
page's own 20 px gutter. Its links are **44 px** tall — the smallest target a
finger hits reliably — where the header's are 14 px of text and nothing more,
because a pointer is exact and a thumb is not.

#### Room left, deliberately

The theme switch is still its own button in the header, because that is what he
asked for — *later*. When later comes it is one row in the panel and one line of
CSS, and the same for a language switch. The comment beside the rules says so,
so the next person does not rebuild the panel to add a row to it.
