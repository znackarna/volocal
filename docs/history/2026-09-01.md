### 2026-09-01 — The release script asks whether the version is already out

1.2.22 was published at 23:01 on 31 August and this session went on building the
same version for another three-quarters of an hour. Nothing asked, and the
promise to check `gh release list` after handing over a publish command — made
on 26 August after exactly this — had been broken twice by then.

So the script asks, and asks `origin` rather than this clone: a tag can be
pushed from anywhere, and the question is whether the world already has this
number, not whether this machine has fetched it. It asks before the twenty
minutes rather than after, beside the clean-tree guard and for the same reason —
the dangerous shape is an installer bearing a version somebody's copy already
has, carrying different bytes.

Being unable to ask is a warning, not a stop. No network is not evidence of
anything.

Checked against the real tags rather than reasoned about: `v1.2.22` stops it,
`v1.2.23` and a made-up `v9.9.9` pass.

**And the thing it could not have caught.** The guard was written while 1.2.23
was building, which left it uncommitted when the installer finished — so the
tree no longer matched what had been built, and the second pass would have
refused. It was set aside as a patch, the release went out from a clean tree at
`1c35d21`, and it is committed now. `scripts/release.ps1` is not compiled into
the installer, so nothing about that release is less traceable for it; the point
is that a repair to the release machinery cannot land in the middle of a
release. The next one goes in before the build or after the publish.

`Cargo.lock` rides along, since the build rewrites it with every version bump
and it has now been a separate stray commit three releases running.

Verified: 1.2.23 published 22:01:32 UTC, the installer on the release is
9 605 700 bytes — the file measured on this disk — `latest.json` and the
signature beside it, and `site.yml` redeployed the page a second later.

## Splitting the large React components: stage one, the tests that come first

`refactor_codex.md` sets out ten stages for taking `Detail.tsx`,
`Settings.tsx` and `App.tsx` apart by responsibility. The work runs on a
`refactor` branch — an exception to the two-branch rule, asked for so that ten
stages do not sit on `dev` half-finished.

**Checked before starting, because the brief said to.** Every figure in it is
right: 3 507 lines and 53 pieces of state in `Detail.tsx`, 2 929 and 22 in
`Settings.tsx`, 1 960 and 33 in `App.tsx`, 187 frontend tests, 248 Rust tests,
build and clippy clean.

**Stage one is characterization tests, and it is the biggest part of the
brief.** `App.tsx` had no test that rendered it at all; `Detail` had five and
`Settings` three. What is written here is the Detail half of it, twenty-nine
tests across four files, none of which names a hook or a component — every one
opens the whole screen and asks it what a reader would ask. That is the point:
the extraction that follows must not have to rewrite the tests that judge it.

The setup moved out first. `src/detail/fixtures.ts` holds the data and the API
double, `src/detail/harness.tsx` mounts the screen. They are two files because
a `vi.mock` factory is hoisted above the imports of the file it is written in:
a factory can reach `fixtures.ts`, which imports nothing of the application,
but reaching `harness.tsx` would pull in `Detail` and, through it, the very
module being mocked. The API double is built once and exported rather than made
fresh per call, because a test of a feature that writes has to reach the spies
the screen is calling.

**What each file pins, and why that one.**

*Search* (`search.test.tsx`, eleven). The one that matters is that closing the
bar forgets the search. Whether the bar is up and what is written in it are two
pieces of state that reset together today; split between two owners they would
stop doing so and nothing would fail to compile. Also the two-character floor,
the count wrapping past the last hit and before the first, Enter and
Shift+Enter, a new query returning to the first hit, and `found` sitting on
exactly one block.

*Notes* (`notesSection.test.tsx`, nine). The one to keep is that deleting asks
first. A note is the only text in the application a person wrote themselves and
that cannot be produced again; the question in front of the deletion is a
decision, not an accident of where the state currently sits.

*Corrections and the shell boundary* (`editing.test.tsx`, nine). Seven for
correcting a block. Two for the boundary the brief names: transcription and
speaker separation are asked for through the shell, which puts a question
first, and a declined transcription must leave no progress bubble behind —
that state used to survive the refusal with no way out of it.

**Three tests were wrong before the code was.** A key press was sent to
`window`, which is not an element and has no `closest`; a class name was
guessed; an assertion dropped a full stop. All three were the test's fault, and
none of them found anything wrong with the screen. Worth recording because it
is the expected shape of this stage: characterization tests written against a
working product mostly fail on the way the question was asked.

Verified: 216 frontend tests pass, TypeScript clean, and the five tests that
existed before are unchanged and still pass.

Files: `src/detail/fixtures.ts`, `src/detail/harness.tsx`,
`src/detail/screen.test.tsx`, `src/detail/search.test.tsx`,
`src/detail/notesSection.test.tsx`, `src/detail/editing.test.tsx`.

## Stage one finished: Settings and the shell

The other half of the characterization tests. 187 tests at the start of the
day, 256 now.

**`SettingsScreen`, eleven tests.** The tabs are the seam the split will follow,
so what is pinned is what has to survive it. That pressing a tab is a choice
and is remembered, while being sent to one is not — arriving from a notice must
not overwrite where the reader last was. That a remembered tab name this build
no longer has opens the first tab rather than an empty panel, which is what
made renaming `application` safe. And the rule the split is most likely to
break: a switch writes the whole settings object, so a tab component saving only
its own field would drop what the other six hold. The dictionary gets four,
being the one tab with data and CRUD of its own.

**`App.tsx`, fourteen tests, and nothing rendered it before.** The two screens
it owns had tests; the thing that decides which is open and what may start had
none. It is the hardest of the three to mount because almost nothing it does
starts on screen — seven backend event streams, the webview's own drag-and-drop
channel, the updater — and the fixtures hand all of them to a test.

The one that matters is the question before a run. With speaker separation off,
transcription is a direct call; with it on, the question comes first and nothing
starts until it is answered. Declining must start nothing at all.

**Two things this stage found out, neither of them a fault.**

The shell polls the watched folder unconditionally. There is no check on
`watch_folder_enabled` in the frontend at all — the backend answers with nothing
when the folder is off, which is what makes `scan_watch_folder` safe to call
every five seconds. Worth writing down because it is exactly the kind of thing
a move can quietly *improve*: a `useWatchFolder` that reads the setting and
skips the call would change when a folder switched on in Settings is noticed.

And `api.detail` in the shell's fixtures answered about a fixed recording rather
than the one the archive had been given, so opening an untranscribed recording
still showed a transcript and the empty state carrying `Přepsat` could not be
reached. A fixture that does not follow the test's own setup is a test that
cannot fail for the right reason.

**Naming.** `screen.fixtures.ts` and `screen.harness.tsx` in each of
`src/detail/`, `src/settings/` and `src/app/`. `scripts/i18n.mjs` skips both
suffixes now, on the argument it already made for `.test.`: their strings are
read by whoever runs the tests and by nobody else, and a Czech transcript in a
fixture is the point of the fixture.

Verified: 256 frontend tests, 248 Rust tests, `npm run build` clean, clippy
clean. No file outside `src/detail/`, `src/settings/`, `src/app/` and
`scripts/i18n.mjs` was touched — the product has not changed yet, which is the
whole point of a stage that only writes tests.

Files: `src/settings/screen.fixtures.ts`, `src/settings/screen.harness.tsx`,
`src/settings/screen.test.tsx`, `src/app/screen.fixtures.ts`,
`src/app/screen.harness.tsx`, `src/app/screen.test.tsx`.

## The split itself, stages two to ten

All ten stages of `refactor_codex.md` are done. The three screens, before and
after:

| | lines | state |
|---|---|---|
| `Detail.tsx` | 3 507 → **1 005** | 53 → **6** |
| `Settings.tsx` | 2 929 → **1 099** | 22 → **11** |
| `App.tsx` | 1 960 → **1 372** | 33 → **21** |

Twenty-nine commits, thirty-eight new source files, and the 256 tests written
in stage one pass unchanged throughout. Not one of them had to be rewritten by
the work it exists to protect, which is the whole answer to whether stage one
was worth its size.

**What was extracted, and what it was given rather than allowed to own.**

`Detail` became seven controllers and eight components. Every hook returns a
named model and named actions rather than a row of setters, and every one of
them is handed the things that are not its business: the player, the screen's
confirmation dialog, telling the reader about a failure, fetching the recording
again. `useRecordingDetail` is the clearest case — it fetches six things
belonging to five owners and hands the whole answer back to the screen rather
than calling into the other four. A hook that distributed would have been the
concentration this work exists to undo, moved one file across.

`Settings` became seven tab panels plus `useDictionary` and
`SettingsNavigation`. The sections of one tab had been scattered through the
file; they are together now, and the DOM did not move, because only one tab is
ever rendered and the order within it is unchanged.

`App` kept its job. It still decides which screen is open, which recording is
chosen, and what may start — what left is the detail of the watched folder, the
folders, the seven event streams and the notices.

**Three things the split refused to do, each for a stated reason.**

`TranscriptPane` was not extracted in stage five. What was left of the
transcript by then was a list of rows with the search and the context menu
around it, and lifting it would have made a component with fifteen props and no
state — the shape the brief warns against. The header waited until stage eight
for the same reason and was taken then, with its props grouped.

`useAiWorkspace` is not a reducer. `dialog` already is the discriminant the
brief had in mind, and the rest of that state does not transition with it: the
summary length and the translation language are standing choices that survive
every window. A reducer would have been the same machine with more ceremony.

`AppDialogs` does not hold `AddRecordingDialog`. That handler is the shell's
own gate — a fresh take goes through the same door as every other start — and
moving the markup would have left the decision behind and carried only the
frame.

**Two behaviours were nearly lost and are recorded because of it.** The player
pill's compacting has hysteresis: the full pill is 290 px and the compact one
83, expanding needs 232 plus room to spare, and a first draft of `DetailHeader`
dropped the two-sided rule, which would have made the pair flap. And
`useRecordingNotes` was first written to hand `String(error)` to the shell,
which would have shown a Rust error code instead of a Czech sentence.

**What is still too tightly bound.** `App` holds twenty-one pieces of state and
the largest remaining group is the wizard, the update check and the add-recording
flow, which are three separate journeys sharing one screen. `SetupWizard.tsx`
(1 819 lines) and `Library.tsx` (1 482) were left alone, as the brief said to.

Verified after every stage and again at the end: 256 frontend tests, 248 Rust
tests, `npm run build` clean, clippy clean. No visual check was made — the
owner said to skip it on the grounds that the interface does not change, and
that is the one claim here nothing automated can confirm.

## Four regressions the split introduced, and what caught them

An architectural review of the finished branch found three faults left behind
by the refactoring and one it had half-fixed. All four had passed 256 tests.

**The improved document stopped going old.** `markAiStale: () =>
ai.actions.markStale` returns the function instead of calling it, and it
reached both the corrections and the speakers. A rewritten block, a renamed
speaker and a removed one all left the document claiming to be current — a
statement about a transcript that no longer exists.

The arrow is a scar of how the move was made. The text surgery replaced the
*body* of a real callback, and the `() =>` in front of it stayed. Worth
recording as the failure mode of that method: it produces code that compiles,
type-checks and reads almost right.

The fix is not a wrapper that calls it, because `useTranscriptEditing` lists
`markAiStale` among the dependencies of `save`, and every `SegmentRow` receives
`save` — a thousand memoised rows on an hour-long transcript. The language
model is built first of the four controllers now and the function itself is
passed.

**The shell re-armed its seven backend listeners on every render.** It handed
the runtime `() => void loadRecordings()`, fresh each time, and the effect that
registers the listeners had it among its dependencies. Every notice, every
progress event, every folder opening unsubscribed all seven and re-subscribed
them asynchronously — a window in which a backend event had nowhere to land.
Everything the handlers reach for lives in a ref now, and the effect arms once.

**A button in the reading window did nothing.** With a saved custom document
and no enhanced transcript, the transcript tab's empty state carries the only
button there is; the split left it setting a mode twice and opening nothing.
`useAiWorkspace` gained `openConfiguration(mode)`, which is what the two lines
in `main` did.

**And the keyboard was still re-arming.** Memoising the search fixed one half;
`goToNextUncertain` still depended on the clock, so the listener moved eight
times a second while audio played. The clock is read through a ref now.

**What this says about the stage-one tests.** They were worth writing — they
carried seven extractions without a line changing — but they pin what a reader
does, and none of these four is a thing a reader does. Three are invisible
until something else goes wrong, and the fourth is a button nobody had reason
to press in a test. Eleven tests were added with the fixes, each checked both
ways: with the fault put back, it fails.

Three of those eleven ask for referential identity rather than for behaviour,
which the brief warns against. They are kept because the property they pin is
real and has now been broken twice, and because the honest alternative —
counting renders of the whole screen — was flaky: how many times a screen
renders while its promises settle is not something a test can hold still.

Verified: 269 frontend tests, 248 Rust tests, build and clippy clean.

## A file name printed as two words

`Volocal.exe` appeared on the `Soubory` tab as `Vo` and `local.exe`, split
across two lines. Found by eye during the visual check of the split; nothing
automated was ever going to see it.

`.settings code` carried `word-break: break-all`, which breaks between any two
letters at the end of every line whether or not the word would have fitted on
the next one. It was there for the neighbouring `<code>`, which holds the
install path — on this machine `D:\Repo\Slobot\src-tauri\target\debug`, long
enough to run out of its card.

`overflow-wrap: anywhere` keeps both: it breaks inside a word only when the
word cannot fit on a line by itself. The file name moves down whole, and the
path still breaks rather than overflowing.

Not a regression of the split — the rule is the same in `main`, and has been
since the card was written. It surfaced now because somebody was looking at
that tab on purpose.

## A colon in the download bubble

`Stahuji {name}` becomes `Stahuji: {name}`, asked for while watching the bubble
report `Stahuji Menší model jazykové ú…`.

The name of a component is a proper name, not the continuation of a sentence.
Read as one, it is a clause with something missing from it; read as a label and
a value, which is what it is, the colon is what says so. The bubble truncates
the name with an ellipsis besides, so the sentence never reached its end
anyway.

`catalog.ts` carries a note that a component name is read with nothing around
it — `Stahuji {name}`, a row in the by-hand list, a line in the failed-items
list — and that `Stahuji Větší` is a sentence with a hole in it. That note was
about the *names*, and it stands. This is the same observation answered from the
other side: the frame admits it is a frame.

English moved with it and the fingerprint was re-recorded, or the strict
dictionary check would have refused the next release.

## The rule that keeps a screen from growing back

Asked for at the end of the day, and it is the right question: the split is
worth nothing if the same file is 3 000 lines again in a year.

`CLAUDE.md` gains **A feature brings its own file**. What it says: a new
feature is written beside the screen, never inside it — its state, what it can
do and the part of the interface that shows it arrive together, and the screen
composes.

**It is deliberately not a line limit.** A long file that does one thing is
better than a short one with an API nobody can read, and a cap would push the
next person towards the second. The section says so in as many words.

What it is instead is the one moment nobody was having. `Detail.tsx` reached
3 507 lines without a single bad decision in it: a feature was added, two or
three values went into the screen because that is one step cheaper than
starting a file, and that happened fifty-three times. Nobody was ever wrong;
nobody was ever asked. The rule asks.

It carries the four things this day paid for and would otherwise forget: a
controller hands back a named model and named actions rather than setters; it
is *given* the player, the dialogs and the error reporting rather than reaching
for them; it does not distribute what it fetches, because one visit brings back
things belonging to several owners and handing them out is the screen's job;
and anything a hook returns that something lists among its dependencies is
memoised. That last one cost two defects in one afternoon and both were
invisible until something else went wrong.

`ARCHITECTURE.md` gained the frontend layout with it. It had the Rust side
module by module and the whole of `src/` as one line, which was fair when
`src/` was three enormous files and is not now.

Files: `CLAUDE.md`, `ARCHITECTURE.md`.

## Vícejazyčné nahrávky: co Volocal dnes tiše ztrácí, a jak to pozná

Jakub přinesl `Paul Bartlett.m4a` — 47 minut kázání, kde australský host mluví
anglicky a tlumočnice převádí do češtiny, konsekutivně, tahy po dvou až čtyřech
vteřinách. Přepis, který k tomu Volocal vyrobil, vypadá úplně.

**Není.** Změřeno na tom souboru:

* z 494 titulků je anglicky **jeden** — ten na 43:08, a prošel jen proto, že si
  řečník chvíli předtím řekl o pauzu a nikdo přes něj nemluvil;
* detekce jazyka po deseti vteřinách vrací angličtinu u **59 z 287 oken**;
* na dvacetivteřinovém vzorku měřeném po délce mluví host 8,6 vteřiny
  a tlumočnice 7,1 — skoro půl na půl.

Přepis se přitom tváří, že pokrývá 85 % nahrávky, protože konce českých
segmentů přes tu angličtinu přetahují. To je horší než viditelná chyba: nic na
obrazovce neřekne, že polovina chybí.

**Měření, které funkci zmenšilo.** První odhad zněl na druhý průchod segmentací
přes VAD a rozdělení mluvčích — tedy na návrat toho, co 7. srpna zmizelo kvůli
rychlosti. Není potřeba. Vynutit druhý jazyk nestačí, protože whisper si nese
kontext a ten ho stahuje zpátky k převažující řeči; rozhoduje délka toho
kontextu. Stejné tři minuty, jediný rozdíl:

| | anglických řádků | anglického textu |
|---|---|---|
| `--max-context 64`, co Volocal posílá dnes | 4 | 150 znaků |
| `--max-context 0` | 25 | 1 008 znaků |

Sedminásobek. Doplnění druhého jazyka je tedy druhý běh whisperu s nulovým
kontextem a slití podle času — obojí aplikace umí, nové je jen to slévání.

Ověřeno i to, co ostatní implementace umí: whisper.cpp tohle nemá a nechystá se
([#3334](https://github.com/ggml-org/whisper.cpp/issues/3334) je otevřené
a označené jako zastaralé), faster-whisper má `multilingual`, ale je to jiný běh
i jiný formát modelu. Postup, který issue popisuje — VAD, kousky, detekce
jazyka, přepis s vynuceným jazykem, slití — je přesně ten, ke kterému jsme
došli.

### Co dnes přistálo

**Charakterizační testy dřív než cokoli jiného.** `whisper.rs` neměl žádný;
teď má osmnáct. Stavba příkazu se vytáhla do `whisper_command`, které si
nápovědu programu bere parametrem místo aby ji shánělo samo — to je celá ta
extrakce a je to jediné, čím jdou argumenty pozorovat bez spuštění procesu.
Chování se nezměnilo. Pinuje se hlavně `--max-context 64` a pojistka proti
smyčce v `load_segments_from_json`, protože běh bez kontextu tu smyčku vrací do
hry a z dlouhé pojistky se stává to jediné, co stojí mezi smyčkou a přepisem.
Stojí to za to i proto, že `whisper-cli` odpoví na neznámý přepínač vypsáním
nápovědy a **návratovým kódem nula** — špatný argument tedy běh neshodí, jen
nevyrobí přepis a ohlásí úspěch.

**Vzorkování.** `transcription/languages.rs` poslechne šest až šestnáct
desetivteřinových oken rozesetých po nahrávce a u každého nechá whisper určit
jazyk. Okna se vyříznou z už připraveného WAV a zapíšou vlastní hlavičkou, ne
přes ffmpeg — jinak by to bylo šestnáct dalších procesů. Měřeno 1,1 vteřiny na
okno, tedy pod dvacet vteřin na celou nahrávku, půl procenta čtyřicetiminutového
přepisu.

Nabídne se, až když se **shodnou dvě okna**. Ne podíl: podíl závisí na tom,
kolik vzorků se vzalo, takže by stejná nahrávka odpovídala jinak při šesti a při
šestnácti. Jedno okno je šum — jméno, citovaná věta, píseň. Okna pod jistotou
0,60 se nepočítají vůbec; na referenční nahrávce mají skutečně české okno 0,86
a skutečně anglické 0,68, a ten nižší průměr je právě ta nejistota, kterou má
podlaha odříznout.

**Databáze.** Nová tabulka `second_language` (jeden řádek na nahrávku, jeden
jazyk, stav `offered | filled | refused`) a nový sloupec `segments.language`,
který je `NULL` u všeho, co vzniklo dřív. Obojí přírůstkově, `SCHEMA_VERSION`
zůstává na 3 — starší build je nezná a nepoškodí je.

**Jedna past, na kterou je test.** Nabídku *nesmí* mazat `delete_segments`:
rozdělení mluvčích i přestavba vět smažou všechny segmenty a zapíšou je zpátky,
a ani jedno není nový přepis. Kdyby se mazala tam, stisk `Rozpoznat znovu` by
odpověděl na otázku, kterou nikdo nepoložil. Maže ji `delete_transcription`
a přepisový běh ji přepisuje načisto.

**Do okna vedou dva příkazy** — `second_language` a `refuse_second_language`.
Odmítnutí se pamatuje a nezahazuje, co se našlo.

Zatím nic z toho není vidět: pruh nad přepisem a samotné doplnění přijdou dál.
Pravidlo slévání — jak ve druhém průchodu odlišit anglický segment od českého —
se úmyslně nepsalo, protože není změřené; měří se dvě varianty proti sobě,
diakritika s minimální délkou a detekce jazyka nad zvukem každého kandidáta.

naměřeno jako šum, pod devíti desetinami toho, co bylo naměřeno jako skutečný

projít 55 a více z 59 anglických oken a odmítne to jedno stray čtení. Skutečnou
pojistkou zůstává, že se musí shodnout dvě okna.

Obě naměřené situace jsou teď testy — `the_interpreted_recordings_own_windows_are_counted`
drží přesně ty tři jistoty, které první pokus zahodil, a
`a_single_language_recording_says_nothing` drží kontrolu i s tím čtením na 0,38.

konci přepisu, takže žádná nahrávka, která už v archivu je, nabídku nikdy
nedostane. U funkce, jejíž celý smysl je *přicházíte o půlku řeči a nevíte
o tom*, to nejvíc odnese ten, kdo má archiv plný starších nahrávek.

### A díra, kterou to odhalilo, je zavřená

Vzorkování běželo jen na konci přepisu, takže žádná nahrávka, která už
v archivu byla, nabídku nikdy nedostala. U funkce, jejíž smysl je *přicházíte
o půlku řeči a nevíte o tom*, to nejvíc odnese ten, kdo má archiv plný starších
nahrávek — přesně ten, pro koho je.

`sweep_second_language` pustí totéž na hotový přepis. Rozdíl proti běhu uvnitř
přepisu je jediný: připravený WAV už neexistuje, takže se udělá a zase zahodí.
To je celá cena, a proto se to musí vyžádat, ne dělat každé nahrávce pro
jistotu.

Stojí ve stejné frontě jako přepis. Ne proto, že dvacet vteřin je hodně, ale
proto, že to pouští whisper — a dva na jedné grafické kartě si berou paměť
navzájem a doběhnou oba později, než by doběhl jeden.

Odmítne se u nahrávky bez přepisu (není co s čím porovnat) a u nahrávky, na
které už něco běží.

### Oprava: to číslo měřilo překlad, ne získanou řeč

Výše stojí, že `--max-context 0` proti dnešním 64 vrátí sedmkrát víc angličtiny.
**Ten poměr platí pro anglický text, ne pro získanou řeč, a rozdíl mezi tím je
celý ten omyl.**

Druhý průchod přes celou nahrávku to ukázal. `whisper -l en` nedělá jen přepis:
kde je zvuk anglický, přepisuje, a kde je český, **překládá**. Prvních
osmdesát vteřin nahrávky mluví česky moderátor a nikdo jiný — a druhý průchod
tam vyrobil třináct anglických segmentů, mimo jiné *„our host, Paul Bartlet,
who here is already three days ago"*, což je věta z českého úvodu přeložená do
angličtiny. Žádná taková věta v nahrávce nezazněla.

Změřeno na celém souboru: ze 642 segmentů druhého průchodu jich 467 vypadá
anglicky a **376 z nich, tedy 81 %, sedí nad zvukem naměřeným jako český**.
V tříminutovém úseku, ze kterého to původní číslo pochází, je z 30 anglicky
vypadajících segmentů nad anglickým zvukem jen 6.

(To srovnání se zvukem má hrubost deseti vteřin, takže u dvouvteřinových tahů
může mýlit oběma směry a 81 % je horní odhad. Úvod nahrávky je ale
jednoznačný a nepotřebuje ho: tam prostě anglicky nikdo nemluví.)

**Co z toho padá a co ne.** Vzorkování — tedy to, co dnes přistálo a co pozná,
že v nahrávce je druhý jazyk — se to netýká vůbec; pracuje nad zvukem a jeho
čísla stojí. Padá levná varianta slévacího pravidla. Rozeznávat podle
diakritiky by do přepisu vložilo 376 strojových překladů vět, které v něm už
jsou správně česky, a **žádné pravidlo nad textem to nemůže odchytit**, protože
překlad a přepis jsou obojí anglický text.

Padá s tím i představa, že druhý průchod poběží naslepo přes celý soubor.
Whisper se musí ptát na angličtinu jen tam, kde angličtina opravdu je.

**Kam dál.** Kandidáti mají vzniknout tam, kde první průchod nenašel nic —
mezery v české stopě jsou jediné místo, kde druhý jazyk může být — a každý
kandidát se má potvrdit detekcí nad svým vlastním zvukem, ne nad svým textem.
To je ohraničená práce: řádově desítky detekcí místo stovek, které by stálo
proměření celé nahrávky nahusto. Změřit se to musí dřív, než se to napíše —
stejně jako tohle.

Zapsáno bez mazání předchozího odstavce záměrně: to číslo šlo do commitu
`8ecfe3f` i do release úvah a je pořád pravda o tom, co měřilo. Neplatí jen
závěr, který jsem z něj vyvodil.

### Doplnění druhého jazyka: mezery mezi slovy jsou celý trik

Předchozí záznam pohřbil slévání podle textu a nechal otevřenou otázku, odkud
brát kandidáty. Odpověď byla v datech, která už archiv má.

**Rozsahy bloků nejsou tam, kde jsou slova.** Na referenční nahrávce pokrývají
rozsahy 46,5 minuty ze 47,7 — proto přepis vypadá úplný. Slova uvnitř těch
bloků pokrývají 29,5 minuty. Osmnáct minut mezi nimi je druhý jazyk, a najít je
nestojí nic: časy slov jsou uložené od začátku.

Z toho plyne postup, který ten překladový problém neodfiltruje, ale
**znemožní**. Whisperu jde jen zvuk, ve kterém první průchod neslyšel ani
slovo. Nemá co překládat, protože slova už jsou napsaná. Kde slepý průchod přes
celý soubor vyrobil třináct vymyšlených anglických vět nad českým úvodem, tenhle
nevyrobí ani jednu — první doplněná věta je až v 1:48 a je hostova.

Mezery se slepí do jednoho souboru s 0,6 s ticha mezi kusy a whisper se pustí
**jednou**. Tři sta samostatných spuštění by strávilo skoro všechen čas
startem procesu a načítáním modelu; ticho mezi kusy je to, co je udrží
oddělené, aby dvě místa z opačných konců nahrávky nesplynula v jednu větu.

Ověřeno ručně na `Paul Bartlett.m4a` před napsáním kódu: 483 českých bloků,
244 doplněných anglických, prokládaně podle času a na správných místech.

**Dvě vady, které to měření našlo, jsou teď pravidla s testem.** Fill vyrobil
`he had a voice` jedenáctkrát nad jediným místem s tichem v celé sadě — dvakrát
může být řečnická figura, jedenáctkrát ne, a pojistka v
`load_segments_from_json` to nechytá, protože ty výskyty nejsou za sebou. A na
okrajích mezer prosakují krátké české věty bez diakritiky. Filtr má tedy tři
pravidla: první jazyk podle písmen, minimální délka, a nejvýš dvě opakování.

`Ask` v `whisper.rs` drží dvě hodnoty, které se mění vždycky spolu — jaký jazyk
se žádá a kolik kontextu se nese. Pojmenovat jazyk bez toho druhého je přesně
způsob, jak by se z druhého průchodu tiše stal obyčejný.

Zápis je v jedné transakci se změnou stavu nabídky, takže selhání kdekoli nechá
přepis přesně tak, jak byl.

**Co ještě není:** nad přepisem není řádek s tlačítkem, takže to zatím nemá čím
spustit. Backend je hotový a otestovaný, chybí ta viditelná půlka.

### A viditelná půlka: jeden řádek, jedno tlačítko

Nad přepisem přibyl pruh, který se objeví **jen** tehdy, když vzorkování druhý
jazyk opravdu našlo a čtenář na to ještě neodpověděl. U jednojazyčné nahrávky
tedy nikdy, a to je na tom to podstatné: funkce, která se u devětadevadesáti
nahrávek ze sta nijak neprojeví, nestojí čtenáře ani vteřinu pozornosti.

Řekne jednu větu — *V nahrávce se mluví také anglicky a v přepisu to chybí* —
a nabídne `Doplnit` a `Nechat být`. Jazyk je pojmenovaný, ne ukázaný kódem;
čtenář se nevybírá který jazyk, kterou část ani jak, protože vzorkování to už
ví a otázka, na kterou se nedá odpovědět z toho, co je na obrazovce, není
otázka, kterou stojí za to položit.

`useSecondLanguage` drží odpověď a tři věci, které se s ní dají udělat.
Nedostane přehrávač ani přepis; dostane `onError` a `load`, protože doplnění
přepíše **všechny** bloky — i ty, kterým se nezměnil text, protože se jim
změnilo pořadí — a obrazovka, která by dál kreslila to, co měla předtím, by
ukazovala starý přepis. Odmítnutí zmizí z obrazovky hned a zápis je to, co ho
udrží pryč; čekat na něj by nechalo pruh stát pod stiskem, který zabral.

Pruh sedí **nad** proužkem se zkratkami, protože je to zpráva o tomhle přepisu,
ne pomoc se čtením — a je to jediná věc na té obrazovce, která říká, že text
před čtenářem není úplný. Bere stejné odsazení i stejnou spodní linku jako
proužek pod ním, aby spolu četly jako jeden pás. Co nesdílí, je tichá barva:
tohle je zpráva k jednání, takže nese akcentovou linku, kterou proužek schválně
nemá. Hotový stav ji zase ztrácí — práce je odvedená, zbývá jen počet.

Pět testů proti celé obrazovce, ne proti hooku. První z nich je ten tichý
případ: u nahrávky v jednom jazyce se nesmí objevit nic.

**Jedna oprava mimo tuhle funkci.** `src/app/screen.fixtures.ts` má vlastní
dvojníka API, který o novém dotazu nevěděl, takže čtyři testy skořápky spadly na
`api.secondLanguage is not a function`. Doplněno tam, kde chybělo.
