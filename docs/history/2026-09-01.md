# 2026-09-01

### 2026-09-01 — The release script asks whether the version is already out

1.2.22 was published at 23:01 on 31 August and this session went on building the
same version for another three-quarters of an hour. Nothing asked, and the
promise to check `gh release list` after handing over a publish command — made
on 26 August after exactly this — had been broken twice by then.

So the script asks, and asks `origin` rather than this clone: a tag can be
pushed from anywhere, and the question is whether the world already has this
number, not whether this machine has fetched it. It asks before the twenty
minutes rather than after, beside the clean-tree guard and for the same reason —
the dangerous shape is an installer bearing a version somebody's copy already
has, carrying different bytes.

Being unable to ask is a warning, not a stop. No network is not evidence of
anything.

Checked against the real tags rather than reasoned about: `v1.2.22` stops it,
`v1.2.23` and a made-up `v9.9.9` pass.

**And the thing it could not have caught.** The guard was written while 1.2.23
was building, which left it uncommitted when the installer finished — so the
tree no longer matched what had been built, and the second pass would have
refused. It was set aside as a patch, the release went out from a clean tree at
`1c35d21`, and it is committed now. `scripts/release.ps1` is not compiled into
the installer, so nothing about that release is less traceable for it; the point
is that a repair to the release machinery cannot land in the middle of a
release. The next one goes in before the build or after the publish.

`Cargo.lock` rides along, since the build rewrites it with every version bump
and it has now been a separate stray commit three releases running.

signature beside it, and `site.yml` redeployed the page a second later.
