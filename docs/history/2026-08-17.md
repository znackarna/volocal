# 2026-08-17

### 2026-08-17 — Three faults in the new first run, all of them inherited rather than invented

1.2.9 was installed and opened, and the screen said three things it should not.
None of the three is a wrong value; all three are what happens when a rule, a
string or a glyph is *reused* without checking what it already promises.

#### The card titles sat at the right edge

`.choice-head` carries `justify-content: space-between` and that is correct
where it comes from: on the other choice cards a name stands left and a size
stands right. In the wizard nothing stands right, so the property pushed the
title to the far edge with the icon left behind.

`.setup-choices .choice-head` set `display`, `align-items` and `gap` — and
inherited the one that mattered. **A shared rule's every property is in force
until it is named**, which is the fault `CLAUDE.md` warns about for rules that
differ only in file order, met here in a different form.

#### *asi minutu* had no number in it

`common.count.minute.one` read **asi minutu**, and beside **4 minuty** on the
next card it looked like a fault — because it is one: the figures are there to
be compared, and one of them had dropped its figure.

It was also saying *asi* a second time. The note under the cards has said
*Časy jsou přibližné* since it was written, so the hedge belonged to the
sentence and the number belonged to the number. All four Czech forms and both
English ones now carry `{count}`, and `approximateMinutes` is `minutes` — the
old name would have gone on describing a rounding the string no longer does.

#### The stop square that could not stop

Worst of the three, because the interface offered a control that did nothing.

`ComponentMarkGlyph` draws a square while a component is running, and in the
module listing that is exactly right: there the mark is a `<button>` and
pressing it cancels that download. The wizard's listing reuses the mark as a
`<span>` — the run is one press and the footer owns it — so what arrived was
the *shape* of a cancel button with nothing behind it.

The glyph is now asked for with `running={false}`, so it stays the arrow. The
ring around it already says the row is working, and stopping is the footer's
button. **An icon must not promise an action its element cannot perform**, and
the comment written beside this mark half an hour earlier said so while the code
did the opposite.

- Files: `src/css/04-settings.css`, `src/SetupWizard.tsx`, `src/formats.ts`,
  `src/locales/cs/common.ts`, `src/locales/en/common.ts`, `sources.json`.
- Verified: `npx tsc --noEmit`; `npm run build` with `i18n:check` and
  `docs:check` clean; `npm test` 138.
- Not verified by machine: the dialog on a machine with no models — which is
  where all three were found, and none of them by a check.

### 2026-08-17 — The mark turns on its side and becomes a rolling mill

> Logo se otočí na bok. Úsměv se odanimuje pryč a nos bude projíždět mezi očima
> jako plát plechu mezi válci lisu, opakovaně. A až převod skončí, tak se vrátí
> do normálu.

**Nothing is drawn for this.** Turned ninety degrees the same four shapes stop
being a face: the two `o` are rollers, the stem is sheet metal, and the smile
has no business in a machine. That is the whole reason the idea holds — a state
that needed anything added would be a second mark rather than a state of the
first.

#### Three things the movement needed

- **The sheet travels along y in unturned coordinates.** It is the parent's
  rotation that makes the journey horizontal. Along x it would run lengthwise
  through the rollers instead of between them.
- **It turns about the centre of the drawing, not of the frame.** The mark is
  30.41 across and 24.10 tall; turning about the box's middle would carry it off
  to one side. And `scale(.861)` with it, which is 26.2 / 30.41 — upright, the
  drawing is longer than its frame is tall, so the rollers would be pushed out
  through the top and bottom. The number is that ratio and not a preference.
- **The sheet sets off with the turn, not after it.** The first version waited,
  and the owner saw the pause: *ten první nos by měl odjet už při otáčení, ať je
  to plynulé*. The rule is not *do not set off early* but *do not reach the
  rollers early* — the sheet starts 26 units outside the frame and takes half a
  pass to arrive, so at 520 and 1100 ms it reaches them 30 ms after the turn
  ends. There is no moment when nothing is happening.

#### The last sheet stays as the nose

> A když to skončí, tak poslední nos co přijede by měl zůstat jako nos.

A pass runs from +26 to −26, so **the nose is exactly halfway**. Stopping is
therefore not a matter of cutting the loop but of waiting for it to reach that
halfway point again and dropping the animation there; the resting state carries
no offset, so the sheet simply stays where it had got to. Only then does the
mark turn upright and the smile come back.

Cutting the loop the moment a transcript finishes would snap the sheet from
wherever it was to the nose, and that one frame would say the whole thing was a
trick.

#### The smile turns about the centre of its own arc

> A úsměv, když se vrací, jako by se přitočil podle osy svého radiusu.

The smile is an arc of radius 8.81 centred at (27.66, 13.81). Turning about
**that** point rather than about itself makes it slide along the curve it is
made of: it does not deform and it does not travel in a straight line, it
arrives along its own path.

It cannot leave by turning alone — it is always the same distance from that
centre, so it only orbits, and at ninety degrees it would come to rest on the
left eye. So the turn carries the movement and a fade carries the departure.

The delay sits on the resting rule rather than on the working one, so it applies
only to the return: the smile leaves at once and comes back after the mark is
upright again. The machine becomes a face, and the smile arrives last.

#### Where it lives, which was the open question

The drop zone stands at the top of the archive whether or not the list below it
is empty, so it is the one place the mark is on screen for the whole of a run.
`Library` already knew which recordings were transcribing; the flag is that list
being non-empty.

The other open question is still open and is deliberately not answered: **the
loop says that something is happening, not how far along it is.** The
application has its own percentages and captions on the recording's own row, and
a mark repeating them would be a second progress bar disagreeing with the first
by a frame.

- Files: `src/Brand.tsx`, `src/Library.tsx`, `src/css/02-library.css`.
- The outline and the pen's mask are dropped once the writing is done. The
  outline would otherwise sit behind the turning machine as an unmoved grey copy
  of the face, and the mask — being the shape of a pen's travel — would cut the
  sheet off mid-journey, since a pass leaves the drawing's own box by design.
- `prefers-reduced-motion` keeps the face a face. Not a slower mill: none.
- The writing itself is 1800 ms rather than 2000, on the owner's word.
- Verified: `npx tsc --noEmit`; `npm run build` with `i18n:check` and
  `docs:check` clean; `npm test` 132; `cargo clippy --all-targets -D warnings`.
- Not verified by machine, and it wants a real transcription: the mill has to
  start when one begins and, whenever it ends, the last sheet has to come to
  rest as the nose rather than jumping there.

### 2026-08-17 — Which state rests is the screen's decision, and the introduction goes

> A na výpisu to otočíme, ať je na stránce archivu logo celé a na hover se
> smrskne. A na detailu to nechme, jak to je. Naopak.

**The archive carries the name; a transcript carries the mark.** The archive is
where somebody arrives and where there is room for it. A transcript is somebody
else's recording and the application's own name has no business taking width
from its title. Either way the pointer shows the other state, so neither screen
hides anything — and the crop is now something a reader causes by opening a
recording rather than something a clock does to them.

#### The timed introduction had to go with it

It held the full name for ten seconds after launch and then closed it. On a
screen whose resting state is now open, that would have contradicted itself
inside those same ten seconds: the name would appear, wait, close — and then
have no reason not to open again.

**Nothing of the idea is lost.** The crop still happens, and it happens where it
means something: on the way into a transcript. That is better than a timer,
because it is caused.

Three things went with the introduction, and each was only ever there to serve
it: `APP_STARTED`, which existed so a ten-second countdown would not restart on
every navigation; `headerIntroPlayed`, which spent it once per launch; and the
`ready` gate, which kept a hand resting on the header at start from cancelling
something nobody had seen yet.

**Two durations became one.** 620 ms was the staged closing and 310 the answer
to a hand. Both directions are an answer to a hand now, so 310 is both — and a
change of state that takes 600 ms reads as an application thinking about it.

### 2026-08-17 — The next number is the next number

> Hele, moc skáčeš po číslech, používejme ty nejmenší verzovací čísla.

**A release moves by one patch.** 1.2.0 goes to 1.2.1, then 1.2.2, whatever is
in it. A minor is asked for, not inferred.

The habit this corrects is worth naming, because it is a habit and it will come
back: reading a release, deciding it *feels* like a feature, and reaching for a
minor to say so. That is grading the work with the version number — and the
number is not a grade, it is an order. What a release contained is in
`CHANGELOG.md` and in this folder, which is where anybody who cares actually
looks.

**1.2.0 was already out when this was said, and the two changes since it —
the mill, and the header's states going to the screens — are 1.2.1.**

### 2026-08-17 — A release refused itself over one missing fingerprint

`release.ps1` stopped before it built anything:

```
CHYBA: en: 1 překladů bez otisku zdroje
Pro vydání to nestačí. Při běžné práci je otisk zdroje jen upozornění.
```

`errors.ai.answer_truncated` — the message added with the truncation fix, in both
languages, with no `i18n.mjs approve en` after it. Without the fingerprint the
dictionary cannot say whether the English still matches today's Czech, which is
a warning while working and a refusal at a release.

**The guard worked, and it also showed a gap in how a release is put together.**
1.2.0 went out carrying the same key without a fingerprint. The checks run in
the first pass and the key was merged after that pass had already run; the second
pass finishes a release and does not check again. Nothing was wrong with 1.2.0 —
the English is correct — but nothing verified that either.

Worth doing something about, and deliberately not done here: a release should
either re-check in the second pass or refuse to publish a build older than the
tip it is being tagged at. Both are changes to `release.ps1` and neither belongs
in the same breath as the release they would have blocked.

### 2026-08-17 — The writing had stopped being visible, and 1.2.1 went out without it

> Ale zase mi tam chybí ta krásná vstupní animace obličeje při načtení apky.

Not nostalgia — a defect, introduced with the mill and released in 1.2.1.

**One flag was doing three jobs.** `drawn` turned on the class that starts the
pen, and in the same breath it removed the outline and the mask. The mask is
what makes the pen visible at all: the reveal is the mask opening over the ink.
So the instant the pen was told to draw, the surface it draws on disappeared and
the face simply appeared, fully formed, 400 ms after the archive opened.

Nothing about the pen was broken. It ran, on time, over nothing.

**The fix is a second state.** `drawn` still starts the pen; `written` says it
has arrived, and only then do the outline and the mask go. The margin between
them is the writing's own duration plus a little — the outline sits exactly under
the ink, so taking it away a frame early would show a hole and a frame late costs
nothing.

The mill needed those two gone for a real reason, which is why they were removed
at all: the sheet leaves the drawing's box on every pass, and a mask sized to
that box would cut it off mid-journey. That reason was right. Attaching it to the
wrong moment was not.

- Files: `src/Brand.tsx`.
- **How it survived review:** the change was verified by types, lint, tests and a
  build, and none of those can see whether an animation is visible. Nobody
  watched the archive open between the mill going in and 1.2.1 going out.
- Verified: `npx tsc --noEmit`; `npm run build`; `npm test` 132.
- Not verified by machine, and this is exactly the kind that has to be: open the

### 2026-08-17 — A ghost row under the filter bar, and five seconds instead of ten

Two small things, reported together.

**The ghost.** Rolling down the archive looks right; rolling back up leaves a
strip of a row that is no longer there, drawn over the one that is. Its position
names the cause: it sits exactly at the bottom edge of the sticky block, which is
where `.archive-sticky::before` and `::after` hang at `top: 100%`.

Those two carry `backdrop-filter`, and a `backdrop-filter` inside a
`position: sticky` block leaves the last frame it sampled behind when the block
moves back up the scroller. Rolling down re-samples continuously and looks
right; rolling up does not. **It is a compositing fault, not a layout one** —
nothing is in the wrong place, one thing is simply out of date.

`will-change: transform` asks for a layer of their own, which is what makes the
sample follow the scroll rather than stick to it. **It is a hint and not a
guarantee**, and this is written down so the next reader does not have to
rediscover the fallback: if the ghost survives, drop the blur and keep the colour
fade, which the comment on `::before` already says carries the effect on its own.

**Five seconds.** Two and a half was *moc rychlé*, ten was tried and read as
long. The name is the only place the application says what it is called, so it
has to outlast a glance away — and it also has to stop being the thing on screen
that has not settled yet.

### 2026-08-17 — A voiced noise before speech, and why the onset correction cannot reach it

Reported with a take made to break it: a few seconds of beatbox, then speech
from about the sixth second. Played back, the words light up from 0:00.

The chain, and every link is behaving as designed:

1. **Speech detection keeps the beatbox.** Silero decides whether a sound is
   speech, and beatbox is made with the voice — voiced, formant-carrying, in the
   rhythm of speech. It is almost certainly labelled speech and left in.
2. **Whisper then puts the block's first word at the start of that region**,
   which is the start of the beatbox rather than of the words. The note above
   `mod onset` says this is not a rare case but *every block of every recording*.
3. **The onset correction has nothing to correct.** `first_audible` looks for the
   first frame louder than −32 dB against the block's own peak; the beatbox is
   loud, so the answer is the very beginning and the shift falls under
   `MIN_SHIFT`.

**The code names this case already.** Measured on a seven-second take opening
with a whistle: *the whistle itself this cannot repair, because it is louder than
the speech; the silence in front of it, it can.* Beatbox is that whistle.

#### Left alone deliberately

Repairing it would mean telling speech from voiced non-speech better than Silero
does, which is the whole job of that model — a classifier in front of it is work
of a different order from anything this correction is, and it would improve a
case that barely occurs. What does occur constantly — silence, breath, room tone
before the first word — is corrected and was measured.

So this is written down rather than fixed, on the owner's word: *jen to dej do
záznamu, teď na to prdíme.* The value of the entry is that the next person to
see a word light up over a noise does not diagnose it from nothing.

- Nothing changes in the repository.
- If it is ever picked up, the thing to reach for is not a better energy
  threshold. Loudness cannot separate these two, because the noise is louder
  than the speech — that is the whole shape of the problem.

### 2026-08-17 — Two hundredths of a unit, and the bottom of an `o`

> Když je animace otočená na boku, spodní část písmenka `o` je uříznutá, jeden,
> možná 2 px.

The scale that lets the mark turn inside its own frame was `.861`, arrived at as
26.2 / 30.41 — the frame's height over the drawing's length. **That ratio assumes
the drawing is centred in the frame, and it is not.** The turn is about
(27.655, 12.13) while the frame runs −1 to 25.2, so there are 13.13 units above
the centre and **13.07 below**. Against a reach of 15.206 the largest safe scale
is 0.8595, and .861 ran past it by **0.022 of a unit**.

Twenty-two thousandths — 0.05 px at the size the drop zone draws it — and it was
plainly visible. **At the extreme of a circle the outline is tangent to the
frame**, so a sliver of overrun does not shave a sliver of shape: it takes a wide
flat bite out of a curve that was about to turn. Reported as one or two pixels,
which is what it looks like, and it is a twentieth of one.

`.84` leaves 0.3 of a unit, which is 0.7 px there.

#### Why the prototype could not have shown this

Its frame is square — 34 × 34 about the same centre — so the rotated mark has 17
units either way against a reach of 15.21 and needs no scaling at all. The
application's face sits in a 26.2 tall box and offers 13.07 downward, so it does.
**The one number that caused the fault does not exist on the page the animation
was designed on.**

That is worth knowing about that page in general: it is the right place to choose
timings, easings and order, and the wrong place to trust anything that depends on
the frame a drawing actually lands in.

- Files: `src/css/02-library.css`, and a comment in

## A second download waits its turn instead of being refused

Pressing *Menší* under `Jazyková úprava` while a model was already coming down
produced a red bar across the top of Settings — **Stahování už probíhá,
počkejte na jeho dokončení.** The same bar answered the download icon on the
models page. The owner's question was the whole design review: *Nejde to prostě
jen přidat do fronty?*

It can, and the refusal was never about the run — it was about the destination.
Two threads fetching one component write the same file and both report progress
for the same id, which is what made the bar jump between two values in an
earlier defect. `install_bundle` guarded that with one process-wide
`AtomicBool`, and a flag can only answer *no*.

So the flag became a queue. `WORK` holds what is in hand and what follows it;
an id already `current` or already waiting is dropped rather than added, which
keeps the old protection exactly and per component, where it belongs; anything
else joins the end. One worker, not several — these are gigabytes over one
connection, and two at once finish at the same moment rather than sooner, with
neither progress bar meaning anything on the way.

Both guards in `commands/downloads.rs` are gone, and with them the branch that
cleared the cancellation flag on the way in to every call. That clearing was
half of an older defect from the other side — asking for a second component
wiped the stop request the running worker was watching — so it now happens
inside `install_bundle`, and only on the branch that actually starts a worker.

**Two races the queue introduced, and what closes them.** Taking the next
component and finding there is no next one are one decision under one lock:
split in two, a call arriving in between sees `running` still true, joins a
queue nobody is reading any more, and is fetched by nothing. And a worker lowers
`running` before its own panic guard runs, so the next call may start a worker
in the gap — the guard therefore carries the generation it was started with and
leaves a newer run alone. Without that it emptied a queue it had never seen.

- Files: `src-tauri/src/download.rs`, `src-tauri/src/commands/downloads.rs`.
- `errors.download.already_running` is renamed `errors.download.busy_installing`
  and reworded, because one caller is left and it means something else: nothing
  can be deleted while the installer is renaming files into the same folders.
- `alreadyRunning` in `SetupWizard.tsx` and `downloadAlreadyRunning.test.ts` are
  deleted. They existed to recognise a refusal that no longer happens.
- Verified: two tests in `download.rs` pin the admission decision — a second ask
  appends, a duplicate is dropped whether it is in hand or still waiting, and a
  finished worker's clean-up leaves the run that replaced it alone.

## Cancelling a download left the row running for ever

*A když jsem klikl na stopku, tak to zůstalo stuck.* The stop square stayed, the
percentage stayed at `0 %`, and nothing was behind either of them.

Three places asked whether a row was working, and all three asked it as a list
of what it is **not**: `!!phase && phase !== "complete" && phase !== "error"`.
`cancelled` is neither of those, so a cancelled row was a row that runs for
ever. Adding `waiting` to the phases would have broken the same three a second
time, which is the argument for the shape rather than for the patch.

`downloadIsLive` and `downloadIsMoving` in `types.ts` name the phases positively
and are the only two questions anything asks now. They are two rather than one
because they are genuinely different: a queued row draws a stop control, because
the same press stops it, but has no percentage, no ring and no claim on the
bubble — an arc frozen at nought reads as a download that has stalled rather
than as one that has not started.

- Files: `src/types.ts`, `src/SetupWizard.tsx`, `src/App.tsx`.
- The new `waiting` phase is emitted for every component admitted to the queue,
  including the one about to start. A row that reports nothing after being
  pressed reads as a press that missed — which is what the red bar was covering.
- The models listing shows `čeká` in the size column for those rows. The guided
  run's list keeps the size and the arrow, because there the whole run is one
  press and that list is what the press is about.
- The bubble ignores `waiting` outright: it arrives for components behind the one
  being fetched, and the bubble would have named the last of them at 0 % while
  another was at 40.
- Verified: `npx tsc --noEmit`; `npm run build`; `npx vitest run` 133;
  `cargo test` 209; `cargo clippy --all-targets -- -D warnings` clean.
- Not verified by machine: start a large model, press a second row, watch it say
  `čeká` and then start on its own; press the stop square and watch both rows

### The silence before a resumed download

*Myslím, že to je ono — než dojde k obnovení přerušeného stažení je tam nula a
vypadá to jako stuck.* It was.

The digest is taken from the bytes as they are written, so a resumed download
has to read back and hash everything a previous attempt left before it can carry
on. On a partially fetched three-gigabyte model that is a full pass over
gigabytes of disk, and it ran in silence: the row emitted `0 %` when the press
landed and then nothing until the first byte came off the network.

It reports now, every 200 ms, and what it reports is not a second kind of
progress — those bytes are downloaded. The bar climbing through them to the
point the last attempt reached is the truest picture available of *picking up
where it left off*.

- Files: `src-tauri/src/download.rs`.
- The pass also reads the cancellation flag now. It had no check at all, so a
  `Přerušit` pressed during a three-gigabyte hash was answered only once the
  hash was over — the second half of the same silence.
- `wizard.manual.queued` is `čeká ve frontě` rather than `čeká`, on the owner's
  word: the row is not waiting for something unnamed, it is behind something.

### Stopping one download stopped the whole queue

*Když jsem měl něco ve frontě a zrušil jsem to, automaticky se smazala celá
fronta, ne jen to, co jsem stopnul.*

Inherited, and honestly so: before this morning there was one download at a
time, so one application-wide cancellation flag was exactly the right size for
the question. A queue makes it the wrong size — a stop control drawn on a row
has to answer for that row.

`Work.stop` holds the ids that have been asked to stop, and both read loops look
at it beside the application-wide flag. Stopping the run still breaks the loop
and reports everything behind it; stopping one component fails that component
and the worker goes on to the next.

Which of the two a control means now follows from what the control says it is:

- the stop square on a row in the models listing — that row;
- the progress bubble's cross — the component the bubble names, because stopping
  four more the reader cannot see from there would be a control doing more than
  it says;
- `Přerušit` in the guided first run — everything, because there the download is
  the errand being abandoned and one component would leave four coming down
  behind a screen that says it stopped.

A component still waiting is taken out of the queue by `cancel_component` and
reported by it, since no worker will ever reach it to report it itself. One
being fetched is left to the worker: it has a part-written file to flush, and a
row reported as stopped while its bytes were still landing would be the same
kind of lie in the other direction.

- Files: `src-tauri/src/download.rs`, `src-tauri/src/commands/downloads.rs`,
  `src-tauri/src/main.rs`, `src/api.ts`, `src/SetupWizard.tsx`, `src/App.tsx`.
- `Work.stop` is a `Vec` and not a `HashSet` because `HashSet::new` is not
  `const` and the static is. It holds one or two ids.
- Verified: a test admits three components, takes one in hand, and stops one of
  each kind — the waiting one leaves the queue, the one in hand is left to the
  worker, and the third is untouched by either.
