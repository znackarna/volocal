### 2026-08-14 — Three tabs back up to five, because three did not help

Yesterday's entry ends with Settings at three tabs — `Přepis`, `Aplikace`,
`O aplikaci`. Jakub opened that arrangement and turned it down in one sentence:

> Ty tři karty nepomáhají. Karta vzhled by měla být zvlášť. A O aplikaci bych
> dal Informace a Aktualizaci bych dal zvlášť.

That is the reason for this change, and it belongs in the record: nothing was
measured, nothing broke — the person the screen is for looked at it and said the
grouping does not answer the question he arrives with. So the grouping changed
and only the grouping. **Every control the simplification removed stays
removed**, because those were dead (`Hledání změn mluvčího`, whose setting no
Rust code reads), harmful (`Počet mluvčích`, which silently overrode `Nevím`),
or derivable from a neighbour (`Řádkování`, `Sledovat složku`). None of that was
about tabs.

**The tabs are `Přepis`, `Vzhled`, `Složky a zálohy`, `Aktualizace`,
`Informace`.**

- `Přepis` is untouched: the model, the recording's language, the speakers, the
  language editing, the dictionary, the band saying what is downloaded, and
  `Pokročilé`.
- `Vzhled` is the appearance card taken back out of `Aplikace` — interface
  language, theme, transcript type and size, and the live sample.
- `Aktualizace` is the check, `Co je nového`, `Stáhnout a nainstalovat` and the
  automatic-check switch, lifted out of the About page. It is the one thing on
  this screen that is neither a setting nor a fact: it is an errand, one press
  of which closes the application and starts an installer. It sat under the
  licence list, which is the last place a reader looking for a new version
  looks.
- `Informace` is what `O aplikaci` was, minus the updates: what the application
  is, what it can do, and what it stands on. Nothing on it can be pressed.
- `Aplikace` is `Složky a zálohy`. **This is the one decision the owner did not
  make for us.** With appearance gone, what was left under that name is the
  recordings folder, the watched folder, the archive's backups with export and
  import, and — on an ordinary installation — the portable copy. Not one of them
  is what anybody would look for behind the word `Aplikace`, and a label that
  does not describe its contents is how the seven tabs got their names in the
  first place. The new one names both halves of what is there: the two folders,
  and the copies you go to once something has already gone wrong.

**Nothing moved between cards.** Every card is the same card with the same
contents; only which tab draws it changed. The one component change is that
`About` no longer takes the four update props — the update block is rendered by
the new `settings-card-updates` section instead.

**The tab names in the code changed with the visible ones**, so `application`
became `files` and `appearance`, `updates` and `about` stand beside them. The
last open tab is remembered in `localStorage` under `settings-tab`, and the
guard that was already there is what makes a rename safe: a stored name that is
not one of `SETTINGS_TABS` opens `Přepis` rather than an empty panel. Every
machine that opened Settings yesterday has `application` in there and will land
on `Přepis` once.

**Every card on every tab has an `order` rule**, including the two tabs that
hold a single card. Alone the number changes nothing; without it, the next card
put beside them takes `order: 0` and jumps above whatever asked for 1 — which is
precisely the defect written up yesterday about the recordings folder.

**Two keys were retired and two added.** `settings.tab.application` is gone from
`cs`, `en` and `sources.json`; `settings.tab.files` and `settings.tab.updates`
are new; `settings.tab.about` keeps its name and says `Informace` / `Information`
now. The appearance tab is labelled from `settings.appearance.title` — the card
that fills it already carries that word, and a second key holding the same word
is a second thing to keep in step. The updates card does the same in the other
direction, taking its heading from `settings.tab.updates`, exactly as the
transcription card takes its own from `settings.tab.transcription`.

### 2026-08-14 — One question at the beginning, and everything follows from it

The owner read the settings screen back and answered it with a decision rather
than a correction:

> Prostě možná by člověk neměl mít na výběr. Prostě má dvě možnosti, rychle
> nebo přesně. Ta podpora pro CPU nebo GPU se stáhne podle toho co má.
> … Jazyková úprava Rychlá vs Přesná, žádné modely in the middle.
> … Prostě na začátku si vybere jestli chce rychle nebo přesné výstupy. A to
> stáhne všechno potřebné. Jazykovou úpravu bych stahoval až potom, až bude chtít.

The wizard already asks `Rychle, nebo přesně?`. What was missing is that the
answer was thrown away the moment the model was downloaded, so every later
question — which language-editing model, which acceleration — had to be asked
again, of a reader who had already said which end of the trade they are on.
**The answer is now written down and read everywhere it decides something.**

**`quality_choice` in the settings record**, `fast` or `accurate`, with
`#[serde(default)]`. Empty is the honest value for every settings record written
before today: nobody was asked. It is not guessed in Rust; `qualityChoice()` in
`types.ts` reads it against `model`, and a machine transcribing with the turbo
model is a machine that answered *rychle* when it was set up. The wizard writes
it from both paths — the two cards, and ticking a transcription model by hand in
the component list, which is the same answer given in a different place. It is
written whether or not the model landed: `model` names a file and must not name
a missing one, while this names a decision.

**The language editor follows it and is never asked about again.**
`EDITOR_TIER` maps `fast` to `editor-model-light` (3350 MB) and `accurate` to
`editor-model-best` (6980 MB). There is no card, no dropdown and no second
question anywhere: the three choice tiles left `Přepis`, the three-tier table
left the wizard, and `editor-model-balanced` is offered nowhere.

**And it is named by nothing it cannot prove.** This is the part of the change
worth reading twice, because the brief for it asked us to check before writing
and the check came back empty. `docs/history/` contains no comparison of the
three models' output — none, on any axis. Every inference ever recorded here was
run with the 12B model alone, because it was the only one installed on the
machine that did the work (`2026-08-02.md`, "Full inference was not run during
development because none of the new 3.35–6.98 GB models was already installed
locally"). The single speed number in the record — 1.2 tokens/s reasoning-on
against about 75 reasoning-off — is 12B against itself with a llama-server flag
changed, not one tier against another. And `2026-08-05.md`, the entry that gave
the three cards their counted sparkles, says it outright: they "trade nothing;
they do the same work with more of it".

So `Lépe opravuje zjevné chyby a drží souvislosti` and `Nejspolehlivější
výsledek` were exactly the middle transcription model's *asi jedna chyba na
odstavec*, deleted yesterday for being measured nowhere. They are not replaced
with a smaller claim. The catalogue now names these three by size —
`Jazyková úprava — menší / střední / větší model` — and describes them by what
follows from a file's size and nothing else: how much memory it needs. Where the
reader meets the editor there is no tier name at all, only one sentence with the
number of gigabytes in it, because at that point which model it is is not
something they can act on.

This supersedes the 5 August decision that gave the tiers one, two and three
sparkles. `EditorMark` is deleted with the cards it marked: a mark that says
"more of the same" is right only where there are three things to tell apart, and
there are none.

**It downloads once, on demand, in the background.** The first press of a
document action on a transcript asks one question — *Chcete z přepisu hotový
dokument?* — with the size in the sentence. Yes starts the download and closes
the dialog: `download` in `downloads.rs` starts a thread and returns, so the
reader carries on reading and the application's own progress bubble reports it
with a way to stop. Pressed again while that runs, the dialog says the model is
downloading instead of offering again; asked once means once. `editor_model` is
written at the press rather than when the file lands, deliberately —
`resolve_editor_model` falls back to whatever is actually on the disk, so a name
ahead of its file is not a dead end, and a listener that had to survive the
reader walking to the Archive would not have survived it. The same press exists
on `Přepis` for anyone who arrives there instead, and does the same thing;
neither walks to the wizard any more.

**`Akcelerace zpracování` and `Změřit rychlost` are gone from Settings.** The
machine picks its backend from its drivers, exactly as the wizard already picks
the programs. A reader choosing here could only choose something slower or
something this computer cannot run — and `choose_compute` then silently
substitutes, which is the defect underneath: the screen went on badging
`používá se` on a card that had never run anything. Verified in `tools.rs`
before this was written: with a stored `cuda` and no `nvcuda.dll`,
`usable_compute("cuda")` is false, the stored branch is skipped, and the next
line down that the machine can run wins.

**So `Nástroje` gained a card that says what actually ran**, `Kde přepis běží`,
built from `.about-panel` — the panel of facts the About page and the archive's
backups already share — rather than from the four choice cards it replaces. It
shows `check.compute`, which is `choose_compute`'s answer and the folder the
next `whisper-cli` comes out of, not the stored setting. Three sentences under
it, at most one at a time:

- a backend was named by hand on some earlier day and this machine can run it —
  it says so, and offers `Nechat na aplikaci`. The same shape as `Odebrat`
  beside the watched folder: when a control is removed, whatever it could set
  must keep a way back, or one press made a year ago is permanent;
- it was named by hand and cannot be run here — it says that, and offers the
  same button. This is the reported case: CUDA on a machine with an AMD card;
- nothing was named, there is a graphics card, and the transcription is not
  using it. With nothing pinned that can only mean the build is not downloaded,
  so it offers to download it. And on a machine with no graphics card at all,
  one line saying so, which is a fact and not a fault.

`compute` therefore left `ADVANCED_DEFAULTS`: a badge reading `upraveno` about a
value with no control on the screen is a badge nobody can act on. It stays in
the settings record, with a comment saying why.

**The shortcut strip has a way back.** Yesterday's entry called permanence "the
trade: one fewer control against one fewer way back", and it is not a trade
anybody needs to make. Dismissing the strip is still a × on the transcript
screen; bringing it back is a keyboard button in the player's row, drawn only
while the strip is hidden — so it costs nothing when it is up, and it is where
the thing disappeared rather than two screens away. `detail.tips.hideHint` still
said *vrátit se dají v nastavení*, which stopped being true when the switch was
deleted; it names the button now.

> V tom ručním výpisu stažení modelů a nástrojů: Rozpoznání mluvčích a detekce
> řeči bych dal do jednoho. Dal bych pryč ty vyvážené modely.

### 2026-08-14 — The owner at the screen: `Výkon`, two editor models, and a floor under both

#### Jazyková úprava: two cards, and nothing to switch off

Three sentences, an hour apart:

> Jazyková úprava nemá smysl. Prostě u ní mají být dva modely na výběr. Žádný
> toggle.

> Volba v průvodci bude jednoduchá. Rychle nebo přesně. Zbytek se zvolí podle
> toho. To samé jazyková úprava.

> Tlačítko Nepoužívat u Jazykové úpravy nedává smysl.

The card is **two choice cards, `Menší` and `Větší`, one of them always chosen,
and nothing else.** The `SettingsToggle` is gone and there is no off state.

**Why there is no off state, written here so nobody adds one back:** language
editing never runs by itself. It happens when somebody asks a transcript for a
document, and nothing is downloaded until they do. A switch would be turning off
something that only ever happens on request. The question the cards answer is a
different one — which model is used when the reader does ask — and that is a
setting, not a switch. A `Nepoužívat` button stood there for one round, built to
answer *how does somebody say they do not want it at all*; the question dissolves
rather than being answered, and the button was deleted rather than hidden.

**`editor_model: ""` was the old off state and is not one now.** It is what a
machine holds when nobody has ever asked for a document, and every reader of it
already treats it as *nothing downloaded yet* rather than *the reader declined*:
`Detail.tsx` offers the download, `tools.rs` resolves no model and reports no
fault, and Settings draws the default card as chosen without claiming the reader
picked it. Nothing had to change for that; it was checked rather than assumed.

**One question in the application, and Settings is where it is revisited.** The
wizard asks `rychle` or `přesně` once and `EDITOR_TIER` turns that into a model —
that is the default, and it is what the chosen card shows until somebody chooses
otherwise. **A card pressed here is stored in `editor_model` and wins**, exactly
as the transcription model chosen a card above wins over the one the wizard
downloaded, and nothing writes over it afterwards. The middle sentence above was
read as *the editor can never be chosen anywhere*, and a version with no cards at
all — an `.about-panel` row naming the model — was built and thrown away. The two
are different things: one question at setup, and a screen where an answer can be
changed later, are the same arrangement the transcription model has always had.

`askForEditor` in `Detail.tsx` was the one place the two could have fought, and
did: it computed the tier from `quality_choice` and ignored `editor_model`, so a
reader with a model chosen and its runtime missing would have been offered a
different model — several gigabytes to replace a working choice with an
inference. It reads the stored value first now.

**Sizes on the cards, one square at two sizes beside them, and no claim about
what comes out.** Pressing a card fetches whatever it still needs — the model,
and the runtime where that is missing too — and the size in the card says how
much that is. A card already on the disk says `staženo`.

#### Menší and Větší, and where an adjective stops working

> Větší a Menší u jazykové úpravy stačí a měly by pro každý být ikona, to platí
> o Přesný a Rychlý taky.

> Stahuji Větší působí divně. Větší co? Model?

Both are right and together they are a rule worth keeping: **a card label and a
catalogue name are two different jobs.** Under a heading reading `Jazyková
úprava` the noun is supplied and `Menší` is correct. In `Stahuji {name}`, in the
by-hand list and in the failed-items list the name stands alone, and an adjective
with no noun is a sentence with a hole in it. So the cards say `Menší` and
`Větší` from the settings dictionary, and the catalogue says `Menší model
jazykové úpravy` and `Větší model jazykové úpravy`. The sentence under each card
is still the catalogue's, because that one reads correctly in both places.

The rest of the catalogue was given the same test. `Rychlý model`, `Přesný
model`, `Detekce řeči`, `Rozpoznání hlasů`, `Přepis na grafické kartě` all carry
their noun already; the three editor models were the only ones that did not. And
the reverse test on the model cards: `Rychlý` and `Přesný` under a label reading
`Model` correctly do not repeat the word.

**No quality claim came back in.** Nothing in `docs/history/` compares these
models' output — the entry above sets that out — so the descriptions say what a
file's size does decide: `Potřebuje nejmíň paměti a je hotová dřív` against `Dělá
totéž s víc parametry a potřebuje na to víc paměti i času`. The added *i času* is
arithmetic about parameter count, not a measurement.

#### Icons on four choices, and one pair that is weaker than the other

- `Rychlý` and `Přesný` on the wizard's quality cards carry `ModelMark`, keyed on
  the model identifier — the lightning is `large-v3-turbo`, the target is
  `large-v3`, the same drawings the model list in Settings has always given those
  two models. The mark moved from `Settings.tsx` to `src/icons.tsx` for that
  reason: the same model must not wear one drawing on the first screen and
  another on the fifth, and importing it out of `Settings.tsx` would have made a
  cycle — the problem `settings/toggle.tsx` was created to solve. The cards
  became `.choice with-icon` with a `.choice-body`, and `.choice-size` moved out
  to the right edge beside where a badge would sit. **This pair is honest in
  isolation**: speed against precision is the trade those two models make, and it
  is the one thing about them anybody has measured (13 August, time alignment:
  3.34 s against 0.56 s).
- `Menší`, `Střední` and `Větší` carry one square drawn at three sizes,
  `sizeSmall` / `sizeMedium` / `sizeLarge`. The same shape at a different size,
  because size is the only thing known about the difference — a drawing that also
  changed shape would be claiming something nobody has measured. **They read as a
  set and are weak alone**, and with two cards on screen the pair is visible,
  while the middle one on an older machine stands by itself and only reinforces
  its word. That is the ceiling for a mark whose meaning is a comparison, and it
  is written into the comment on the glyphs so nobody re-derives it. This is not
  `EditorMark` returning: that counted one, two and three sparkles and was a rank.
  A square at its own size is a size.
- `Grafická karta` and `Procesor` on `Výkon` carry `graphicsCard` — a new glyph,
  a board with its fan and pins — and `compute`, which was already a processor
  drawing. Two different objects rather than two chips, because telling them
  apart at 22 px is the whole job.

#### `Výkon`: the switch back, and CUDA never asked

> Kde přepis běží a tam bych dal CPU a GPU možnost přepnutí. Ale automaticky by
> to vždycky volilo tu rychlejší variantu.

> A dej tam stejnou kartu jako má výběr modelu u přepisu, ne tu trapnou záložku.

> A dej pod to info ikonu: Aplikace automaticky volí výkonnější variantu.

> Kde přepis běží změň na: Výkon

The entry above removed that control and left the card as a panel of facts. The
panel stays; the choice comes back above it as **two `.choice with-icon` cards,
the same ones the transcription model uses** — a segmented control was built
first and rejected in those words — and the card is headed **`Výkon`**.

**Automatic is not a third card.** It is the absence of a pick: what a fresh
installation has, and what `Automaticky` puts a machine back to. A third card
would say the work can happen in three places, and it can happen in two. What
says so instead is the note under the cards, `Aplikace automaticky volí
výkonnější variantu.`, which describes the resting state and does not promise
that the application overrides a deliberate choice — it does not, and the panel
below is what says whether a choice was honoured.

**CUDA against Vulkan is never asked, and that is the point of the shape.** They
are two builds of one thing for two kinds of card, and which suits the card in
this machine is a fact about its drivers. Asking it is how somebody came to have
`cuda` stored beside an AMD card — the build found no device, whisper fell back
to the processor, and the screen went on badging `používá se` on the card nobody
was using. So `settings.compute` gained the value `gpu`, which names the card
without naming a build, and `choose_compute` resolves it: `GRAPHICS_BUILDS` is
CUDA then Vulkan, filtered by what is downloaded *and* by what the drivers allow.
The same expression is what automatic prefers, which is why it is written once
and called twice — automatic taking the fastest available option and `gpu`
meaning the fastest card build are the same sentence.

**Automatic stays distinguishable from a pick**, because it is a stored value of
its own and not an absence in the database: a machine on `auto` follows a driver
appearing or disappearing, and one on `gpu` goes on asking for the card across
both. `cuda` and `vulkan` in older settings records still load, are still
honoured where the machine can run them, and are drawn as `Grafická karta` — the
position they meant. They are not rewritten on sight; a screen that quietly
edited a stored value while being looked at would be a worse habit than a
two-word translation in `computeMode`. The first press of either card replaces
them.

**The cards carry no `používá se`**, on the owner's word — *ta karty používá se
je v bloku výkonu nadbytečná*. A card drawn as chosen already says it is the
one, and two marks for one fact is noise. What the badge was carrying is the
opposite case and stays: the chosen card wears `missing`, the danger colour the
module tiles use, exactly when what ran is not what was picked. **The card is
quiet when it agrees and speaks when it does not** — an empty state there is
correct, and the comment says so, because the next person to see it will be
tempted to fill it.

The `Používá se` row under the cards is kept for a reason the cards cannot
cover: it is the only place that says *which* graphics build the drivers settled
on, which is the answer for a machine on automatic that wants to know where it
ended up.

**What could not be honoured is said, with the reason, and fixed where it can
be.** The substitution inside `choose_compute` is silent by design, because a
transcription must run; this card is the one place it is not silent. Three
sentences, at most one at a time:

- the card is idle with a driver present — with neither card picked the sentence
  says the build is not downloaded, with `Grafická karta` picked it says the
  choice could not be met and what ran instead, and both offer the download;
- `Procesor` picked and the transcription running on the card: the wizard used to
  download one build, and on a machine with a graphics card it was not the
  processor's. Same row, same button, pointing at `whisper-cpu`;
- no supported card at all, which is a fact and not a fault, unchanged.

`compute` stays out of `ADVANCED_DEFAULTS`: `Zpět na výchozí` restores what its
own block shows, and a reset that moved a control on another tab is one nobody
watching it could see.

#### A floor under both: `whisper-cpu` and `editor-cpu` on every first run

> Jazyková úprava na procesoru by se měla taky stahovat defaultně.

`catalog()` in `download.rs` recommends `whisper-cpu` (17 MB) and `editor-cpu`
(45 MB) unconditionally now, rather than only where there is no usable graphics
card. Two reasons, both in the comments where the change is made:

- **whatever the reader can end up pointed at has to exist.** A `Procesor` card
  naming a build that is not on the disk is not a choice — it would be answered
  by `choose_compute` finding nothing, falling through to the card, and the panel
  having to explain that the answer was no. That is the silent substitution this
  card exists to stop, arriving through the control instead of around it;
- **a driver that breaks needs somewhere to fall back to.** A graphics build is
  useless the moment its driver stops loading — a Windows update, a card swapped
  out, a laptop on its integrated chip.

`editor-cpu` is the runtime, not a model: the two Gemma models are 3350 and
6980 MB and stay on demand. `editor-vulkan` (150 MB) also stays on demand and
comes down with the model it runs, on a machine that can use it — the fast path
can wait for the thing it makes fast; the floor cannot.

`whisper-cpu` joins the guided selection through `root`, which takes every
recommended `program`; `editor-cpu` is in the `editor` group and is added by name
in `EDITOR_RUNTIME_COMPONENTS`, beside `DIARIZATION_COMPONENTS` and for the same
reason. `totalMb` reduces over that same selection, so **the number on the
download screen is the number that downloads** — roughly 1.25 GB now.

#### Two more moves, and one sentence that had gone quietly false

> Jazyk nahrávky dejme jako samostatný blok

`Jazyk nahrávky` has a card of its own again, its second move today: the old
`Jazyk a detekce řeči` lost its switch, the one remaining field was folded onto
the model card, and it reads better standing up — what language is spoken is a
fact about the recording, not a property of the model, and it sat under a column
of choice cards as an afterthought. **The heading carries the longer name**;
`Jazyk` alone stood two tabs from `Jazyk aplikace` with nothing to tell them
apart, and a heading is a worse place than a label to leave that. The dropdown
below it has no label of its own — the heading is the label — and takes `Select`'s
`description` so a screen reader still hears the name.

> Řeč a mluvčí → Detekce řeči a mluvčích

The by-hand list's group heading over `vad` and `model-hlasy`. Both detect
something in the sound — one where speech is, the other whose it is — and the old
name read as a heading over the subjects rather than over the work. Both genitives
are deliberate and the context entry now says so.

> Zobrazuje pouze stažené modely. Tohle už neplatí, ne?

Checked in the code rather than from memory, and **the sentence was true**: the
model card lists `check.found_models`, read off the disk, so it shows what is
installed and nothing else — one card on a machine with one model — and pressing
a card downloads nothing. That is also what keeps a machine set up before today
working: `settings.model` may hold `large-v3-q5_0`, the middle model nothing
offers any more, and because the list is the disk rather than an offer it is
still shown, still named by `domain.model.large-v3-q5_0`, and still the chosen
card.

What the same test caught instead was the sentence beside it. `settings.transcription.description`
still read *Model, který nahrávku přepíše, a jazyk, kterým se v ní mluví* on a
card the language had just left — false by one change, and unnoticed. It names
the model only. And `modelNote` was true but useless: it said what the list does
not show without saying where the rest are, so it says both now. The check that
found it is worth keeping: not *does it read well*, but *would a reader who
believed this be wrong*.

**The `Používá se` row is deleted.** The previous entry argued for keeping it,

- **picked and refused** — the one case worth ink: what ran, why the pick could

**`Aplikace sama zvolí výkonnější variantu.` moved onto the control that does

whatever was already running — `onGraphicsCard ? "gpu" : "cpu"` — so the switch
changes who decides and never where the work happens.

> Ten toggle dej pod ty karty.

**And it sits under them**, which settles the question the shape had left open:
the cards stay visible while it is on. A switch beneath them reads as a
qualifier on what is above it — *these two, and let the application decide
which* — and it means somebody can see where their transcript runs without
touching anything. While it is on, the highlighted card is what the drivers
settled on rather than what anybody picked, which is the switch's effect made
visible; pressing a card turns the switch off and takes that card, which is the
most direct reading of what pressing one means. The red `missing` state cannot
occur while the switch is on: with no instruction to contradict,

### 2026-08-14 — The bin, and the row it needed

Asked for four times before it was built, which is a scheduling failure worth
recording: it was called "its own commit" and that put the only item in the
round with a backend behind a queue of copy edits. It should have gone first.

**The backend is the previous entry's commit** — `remove_component`, six tests,
187 to 193. This is the screen.

**Two marks, chosen by state, in one column of one width.** *Checkbox nedává
smysl u stažených, tam to má být to zelené kolečko s fajfkou.* A ticked,
disabled checkbox was a control pretending to be a fact: it looked pressable and
refused. The green circle says the one true thing about that row — this is here
— and a row with nothing to select has no checkbox at all. The column is 18 px
whichever mark is in it, because a checkbox and a 16 px circle differ by a few
pixels at their natural sizes and a list whose text left edge moved with each
row's install state would read as a rendering fault rather than as a
distinction.

**The size is on every row**, downloaded or not. It was the tick's slot; the
tick has moved to the mark column where it belongs. What a component takes up is
the question somebody has when they are looking for space to get back, and it is
exactly the row with the bin on it that they need it for.

**The bin is drawn only where deleting means something exact.** `removable`
comes from Rust, answered in `catalog()`, and is false four ways: nothing
installed, the model `settings.model` or `editor_model` is using, and the two
programs that unpack into the shared `bin` root. **No dead button anywhere** — a
row that cannot be deleted has no bin, rather than one that refuses when
pressed. The command refuses regardless, because a drawing is not a guard.

It is 26 px, `.segment-actions`' icon button, which `CLAUDE.md` documents as the
small one: this sits in a 40 px row beside 13 px type and the 32 px circle would
have been the heaviest thing on a line whose whole point is to be quiet. Grey
until the row is under the pointer, then the danger colour — the only
irreversible thing on the screen should not be the first thing the eye lands on
and must be unmistakable once reached. **Shown on `:focus-visible` too**: a
control that appears only under a pointer is one somebody on a keyboard cannot
find.

**It asks, and names the space.** `ConfirmationDialog` with `destructive`, whose
focus starts on Cancel — that component was built for exactly this shape, so a
blind Enter deletes nothing. *Uvolní se {size}. Stáhnout to jde kdykoli znovu,
ale znovu to potrvá.* The second sentence is the one that matters and its
context entry says so: deleting is not irreversible, it is **expensive**, and
for a seven-gigabyte model the undo is the whole download again. A dialog that
said *this cannot be undone* would be false; one that said only *are you sure*
would be useless.

**The list is reloaded from `catalog()` afterwards rather than edited in
place.** `removable`, `complete` and the tick all come from Rust reading the
disk, and guessing any of them here is how a screen comes to disagree with the
thing it is describing.

One thing guarded that cannot currently happen: the bin's handler stops the
click reaching the `<label>` it sits inside. A removable row's mark is the green
circle rather than an input, so nothing would toggle today — but the day this
list draws a checkbox beside a bin, the defect would be a deleted component and
a silently ticked row.

### 2026-08-14 — `Model přepisu`

> Model
> Model přepisu

The transcription card's third name in a day, and each rename fixed the one
before it. `Přepis` was its tab's own word. `Model` stopped that and was right
until the language editor became a choice between models too — at which point
`Model` named two cards on one screen and told them apart nowhere. **The
qualifier is the distinction rather than decoration**, which is the same reason
`Jazykové modely` became `Jazykové modely pro přepis` in the by-hand list this
morning: both breaks were caused by the same change, and both are the same fix.

**The key stays `settings.transcription.model`**, and the rule that decided it is
the one written down when `settings.tab.tools` was retired: internal follows
visible. A key named `.model` holding `Model přepisu` is not the stale borrowing
that rule exists to catch — `settings.tab.tools` holding `Výkon a modely` was
stale because the identifier named one thing and the value another. Here they
name the same thing and the value is more precise about it. One user, one key,
no churn.

**And `Jazyková úprava` is not a mismatch beside it**, which was worth checking
rather than assuming after the by-hand list's headings turned out to be one. The
group headings were halves of one split, and halves have to be told apart on the
same axis or the split looks accidental. These are six cards on a tab — `Model
přepisu`, `Jazyk nahrávky`, `Mluvčí`, `Jazyková úprava`, `Slovník`, `Pokročilé`
— which are not halves of anything: they are a list of subjects, already mixing
things with an activity and an adjective. `Jazyková úprava` names its feature
the way `Slovník` and `Mluvčí` name theirs.

Renaming it to a thing would make it worse, not better. `Model jazykové úpravy`
would read as `Model přepisu`'s twin and make the two cards look like one pair,
which they are not: one decides how a transcript is made, the other whether a
second document exists at all. The card is about the feature; the models inside
it are how the feature is set up. **Not renamed, and the owner has not asked.**

### 2026-08-14 — Both editor models described the same way, and the sentence stops where the evidence does

> Větší
> Gemma 4 12B. Více parametrů potřebuje víc paměti i času.

Used exactly, and it settles a question that had been open since morning. **The
owner's sentence names the model and then states only what follows from the
parameter count.** Nothing about the output. That is the honest form of the
distinction, and it is what four earlier attempts on this branch were circling
without landing on.

**So `Menší` is built the same way**: `Gemma 4 E2B. Méně parametrů potřebuje míň
paměti i času.` Same construction, same stopping point, and **no counterpart
claim invented to balance the pair** — the asymmetry a reader expects, that the
bigger one is better at the job, is precisely the thing nobody here has evidence
for. `docs/history/` contains no comparison of these models' output; the only
inference ever recorded was run with the 12B alone because it was the only one
installed.

Two things the rewrite quietly fixed. The old smaller-model sentence said
`nejmíň` — a superlative over a set of three, on a card that is one of two — and
`hotová`, feminine, agreeing with nothing on the screen. And the old larger one
opened with `Dělá totéž s víc parametry`, which is a claim about the output
after all: *the same work* is exactly what has not been measured.

**The context entries now carry the rule rather than the conclusion.** Both say
the sentence ends at memory and time deliberately and that *a je přesnější* must
not be helpfully appended, because the difference in memory and time is
arithmetic about a file and anything past it is not. They also say the product
name keeps its digits and capitals in every language. `i18n:check` had no
objection to `Gemma 4 12B` — the hard-coded-text scanner reads components rather
than dictionary values, so a product name inside a translated string is not
something it can mistake for untranslated copy.

`Střední` is left alone. Its sentence does a different job — it says why a model
nothing offers is on the screen at all — and rebuilding it to this pattern would
delete the only thing that explains its presence.
