# 2026-08-31

### 2026-08-31 — The three pieces of ballast, and what each one turned out to be

Point B of `docs/cleanup-plan-2026-08-28.md` listed three loose things and said
of all three: find out what they are, then let the owner decide. Two of them
answered themselves in the looking, and the third is a decision he still has.

**`docs/site/volocal-page.html` is not a mystery, it is a build product.**
`bundle.py` line 14 names exactly that path as its output when the script is
run with no argument — the page in one file, fonts and scripts inlined. The
copy in the working tree was written on 28 August at 09:27, is 780 kB, holds no
external reference, and has never been tracked in this repository's history.
It is rebuilt every time the page is handed to somebody, so a committed copy
would be stale by the afternoon. It goes into `.gitignore`, and the file stays
on disk where it was made.

**`site-on-vercel` was already gone.** Its one commit, `2d4b96c`, is an
ancestor of `main` — the branch was merged and deleted between the plan being
written and this session. The plan is three days old and this line of it had
expired.

**`prepinac-v-bundlu` is behind `dev`, not ahead of it.** Both its commits
were redone on `dev` rather than merged, which is why `git cherry` still calls
them unmerged: the patch ids differ, the content does not. The language-choice
script in `index.html` is identical line for line to the one `dev` carries, and
both history entries are in `docs/history/2026-08-26.md` already. The one line
where the two genuinely differ is the one that matters, and the branch has the
wrong side of it: it rewrites the bundle's language switch to
`https://znackarna.github.io/volocal/en/`, and Pages was switched off on the
27th. `dev` writes `https://volocal.app/en/`. Merging the branch would put a
dead address into every bundle handed over. Comparing the tips, it would also
take 281 lines out of the day file and drop the removal of the reader-counting
script. There is nothing in it to save.

**Dependabot's PR #214: the six pins are honest, three of them are aimed at
lines that no longer exist.** Every SHA in the pull request resolves to the tag
its comment claims — checked against each action's own repository, all six
match. But `configure-pages`, `upload-pages-artifact` and `deploy-pages` were
deleted from `site.yml` on `dev` when Pages was switched off, so half the pull
request is a bump to steps that are on their way out. Of what is left,
`checkout` v7 blocks checking out a fork's pull request under
`pull_request_target` and `workflow_run` — neither trigger is used here — and
all three want Node 24, which the GitHub-hosted runners this repository uses
already have. The one hazard is in the half that is going away:
`upload-pages-artifact` v5 stops including dotfiles, and `main`'s `site.yml`
still writes `_site/.nojekyll`. Merged into `main` on its own, that bump would
quietly hand Pages an artefact without the file that tells Pages not to build
the site with Jekyll.

**And the reason a pull request like this keeps ending up stranded**:
`.github/dependabot.yml` names no `target-branch`, so Dependabot opens against
the default branch, which is `main`. Every monthly bump therefore arrives on
the one branch this project does not work on. That is a one-line fix and it is
his to make, together with what to do with #214 itself.
