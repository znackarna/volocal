# Change log — 2026-08-12

### 2026-08-12 — An archive from a newer version is refused, not guessed at

The failure of 1.0.5 had two halves. The leftover tables were fixed in 1.0.6;
this is the other half, and it is the one that would have mattered more.

When 1.0.4 opened an archive 1.0.5 had migrated, it looked for `nahravky`, did
not find it, and its `CREATE TABLE IF NOT EXISTS` made an empty one. What saved
the owner from a worse morning is that the *next* start crashed. Had it not, the
application would have opened cheerfully and shown an archive with nothing in
it — no recordings, no transcripts — while every word was still on the disk.
That is the worst thing this application could tell somebody who has lost
nothing.

- The archive now carries the schema it was written for, in the settings table,
  written last so it only ever claims a schema it actually reached.
- `open` reads it before it renames or creates anything. A number higher than
  this build knows is `ArchiveFromTheFuture`, and the archive is returned
  untouched.
- The startup dialog tells the two cases apart, because they ask for opposite
  actions. A damaged archive wants a backup copied over it. This one wants
  nothing done to it at all: *"Aktualizujte Volocal… S archivem nic nedělejte —
  je v pořádku a nic v něm nechybí."* Telling its owner to copy a backup over a
  perfectly good archive is the one instruction here that could actually destroy
  work.
- It cannot reach the builds already installed. It stops the next migration from
  repeating this one.
- One thing worth remembering from writing it: `klice` keeps its value in
  `hodnota` and `settings` in `value`, and this runs *before* the rename. Asking
  for the wrong one is not a missing row that `optional()` absorbs — it is a
  missing column, and it fails. The pair is now chosen together.
- Three tests: that opening writes the number down, that a higher number is
  refused by name and the archive left exactly as it was, and that an archive
  with no number is opened normally and given one.
- Files: `src-tauri/src/db.rs`, `src-tauri/src/main.rs`.
- Verified: `cargo test` (160), `clippy -D warnings`, `fmt`, `npm run build`.

### 2026-08-12 — The Dependabot alert, and why it was dismissed rather than fixed

Alert 6: unsoundness in `glib`'s `VariantStrIter`, fixed in 0.20.0, and this
project has 0.18.5 in `Cargo.lock`.

It is dismissed as not used, on evidence rather than on a shrug:

- `cargo tree --target all -i glib` shows it arriving through `gtk`, `gdk`,
  `webkit2gtk` and `wry` — the Linux webview stack.
- `cargo tree --target x86_64-pc-windows-msvc -i glib` prints nothing. For the
  only target Volocal ships, it is not in the dependency graph and never
  compiled into anything released.
- `cargo update -p glib` locks 0 packages: 0.18 is what the gtk-rs versions
  Tauri pins require, so it cannot be moved without Tauri moving first.

Written down because a dismissed alert is exactly the kind of decision that gets
rediscovered later as a mystery. If Volocal is ever built for Linux, this stops
being true and the alert should be reopened.

# Change log — 2026-08-12

### 2026-08-12 — A way back from a backup, inside the application

The dialog that appeared when 1.0.5 could not open the archive printed a
procedure: save the file aside, copy the newest backup over it, rename it to
match the archive. It is sound advice and it was the only way back — work with a
file manager, at the one moment somebody is frightened, and the only place in
this application that asks for that.

Backups could be made and counted and their folder opened. The other half is
here now: a folded-away list of them by date and size, and a Restore beside each.

What `restore_backup` does, in the order it does it, because the order is the
whole thing:

1. The name is checked against the backup directory's own listing. A path
   arriving over IPC does not get to say which file may replace an archive.
2. The archive as it stands is copied aside as `whisp-before-restore.db`.
   Restoring is a decision somebody can regret within the minute — usually by
   picking the wrong date — and without this there is nothing to regret back to.
3. The open connection is replaced with one to `:memory:`, which closes the
   file. Windows will not replace an open file, and a half-copied archive is
   exactly the damage this exists to undo.
4. The backup is copied over and the write-ahead log removed with it: a `-wal`
   belonging to the old file would be replayed into the new one.
5. The archive is opened again through `open`, so a backup written by an older
   schema is migrated on the way in — and one from a newer build is refused by
   the guard added this morning rather than half-read.

The archive is reopened whether the copy worked or not. Leaving the application
holding `:memory:` would make every screen answer with an empty archive, which
is the lie this whole day has been about. The window reloads afterwards: what is
on every screen came from the archive that was just replaced.

Also: `SettingsDisclosure` can now be told when it is first opened, so the list
is fetched then rather than on every visit to the Files tab.

  `src/api.ts`, `src/Settings.tsx`, `src/css/04-nastaveni.css`, the dictionaries.

### 2026-08-12 — The report, for the times the application will not start

The button that copies the technical details lives in Settings, and Settings
needs the application to have started. So the one moment somebody most needs to
hand the state over is the moment they cannot reach the thing that hands it
over. This morning proved it: the dialog said what had gone wrong and there was
no way to take the text out of it.

- A start that fails now writes `volocal-problem.txt` beside the log, before the
  dialog appears, and the dialog says where it is. It holds what a running
  application would have put in a report except the part that lives in the
  archive — version, system, both paths, the failure, and the tail of the log.
- A file rather than the clipboard: nothing is running that could put anything
  on one, and a path can be read out of a dialog and typed.
- And in Settings, beside the copy button, a second one that opens the log
  itself. The report carries sixty lines; a transcription that ran for an hour
  leaves more, and somebody may simply want to read it.

- Files: `src-tauri/src/diagnostics.rs`, `src-tauri/src/main.rs`,
  `src-tauri/src/commands/settings.rs`, `src/api.ts`, `src/Settings.tsx`,

### 2026-08-12 — Two lists doing the same job, made to look like it

Reported from the screen, with two pictures: the backups and the components sit
on the same settings tab, do the same thing — a column of things with a value
beside each — and looked nothing alike. One a bordered panel on its own ground,
the other bare rows with rules between them.

- The backups list now wears `.check`'s surface exactly: same border, radius,
  ground, 14 px inset, hairline between rows and 13 px type. Only the row is
  taller, because this one carries a 34 px button.
- The dates lost their tabular figures. Those are for numbers read down a
  column; a date is a sentence of digits, and monospaced, `12. 8. 2026 10:58`
  falls apart into widely spaced characters. The size keeps them — it is a
  column.
- The two buttons under the components list get 18 px above them rather than 14.
  A bordered panel ends on a line, and a button 14 px under a line reads as
  stuck to it: the amount that looks generous under text looks tight under a
  frame.

**And a real defect, seen in the picture rather than in any check.** Every
backup announced itself as `1 420,0 GB`. `dataSize` speaks in megabytes and the
file system speaks in bytes, and the number went straight through — a 1.4 MB
archive claimed to be a terabyte and a half. Nothing failed; it just lied.

**And a rule that had gone missing without a word.** `.diagnostics-actions` was
lost resolving a rebase conflict yesterday, while `.diagnostics-copy` stayed
behind matching nothing. The buttons only looked right because `.button` is
`inline-flex` and happened to sit side by side anyway. This is exactly the
silent loss the class rename was careful about all day, arriving through the
back door — a merge, not a rename. There is now a check for it in
`orphans.mjs`-shaped form: nine classes are used in markup without a stylesheet
rule, all of them values compared in a ternary rather than real classes, and
that number has not moved.

- Files: `src/Settings.tsx`, `src/css/04-nastaveni.css`.

### 2026-08-12 — Correcting entry: one rule, and it goes under the button

The entry above put the folded-away extras at the foot of their cards and gave
them a rule. It kept the action row's rule as well, so the card ended with two
lines a few lines apart and a single row of text between them. Seen on screen
within the minute, and it is worse than what it replaced.

The rule belongs *under* the action row, not above it. On these two cards the
content above the row is already framed — the module tiles, the backup summary —
so a rule there draws the same boundary twice. `.spaced` is `.separated`'s
distance without its line, and the only rule left on the card is the one that
separates it from the thing folded away at its foot.

`.separated` stays as it was for the cards where the content above is plain
fields or prose, and the line is the only boundary there is.

### 2026-08-12 — What a backup holds, instead of what it weighs

`1 387 MB` is what a file manager says about a file. Nobody chooses a backup by
it. They choose by whether the recording they are missing is in there, and the
nearest honest answer is how many recordings it has and how much audio that is:
`12 přepisů · 6 h 12`.

- Read **read-only**, and that is the whole reason `backup_contents` exists
  rather than calling `db::open`: opening a backup the ordinary way would
  migrate it, and listing nine of them would rewrite nine files.
- Both schemas are tried, `recordings` and `nahravky`. The point of a backup is
  that it is old, so the old name is not a special case here — it is the
  expected one.
- Anything unreadable answers nothing and the row simply says less, rather than
  the list refusing to appear.
- The size moved to the tooltip, where a file's weight belongs.
- No new dictionary entries: `transcriptCount` and `archiveDuration` already
  say these two things everywhere else in the application.

- Files: `src-tauri/src/commands/backups.rs`, `src/api.ts`, `src/Settings.tsx`,
  `src/css/04-nastaveni.css`.
