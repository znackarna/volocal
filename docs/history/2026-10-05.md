# 2026-10-05

### 2026-10-05 — `volocal-tui` archived

The owner's call, after a release review of 1.3.0: the full-screen terminal
program is *spíš gimmick* for now. Its one use nothing else covers is reaching
Volocal over SSH, which almost no Windows user has switched on; the people
who transcribe recordings never open a terminal. It cost fourteen files to
keep in step with the engine, six megabytes in every installer, and the
review found it would not have reached the installer at all (a tauri-cli
2.11.4 bug skips every program in `src/bin` after the first), that a file
dropped onto it on Windows types the path as commands, and that a stale
"transcribing" row makes it wait for ever. `volocal-cli` stays: scripts, batch
runs and the Linux and Docker work all stand on it.

**Removed, not lost.** The last commit with the program is `3df4f14`
(`volocal-tui colours the words said so far, as the window does`). To bring
it back:

```
git checkout 3df4f14 -- src-tauri/src/bin/volocal-tui docs/tui-plan.md docs/prototypes/volocal-tui.html
```

and restore its three dependencies in `src-tauri/Cargo.toml` from the same
commit (`ratatui`, `terminal-colorsaurus`, `rodio`) with a `[[bin]]` entry for
it beside the one for `volocal-cli`. The review of 2026-10-05 lists what it
would need before a release.

What stayed, because the command line uses it: the run lock
(`run_lock.rs`), the window's card for a run in a terminal, and
`volocal-cli/common.rs`, which the TUI included by path. Its comment, the
Library card's comment and two translator notes no longer name the TUI.

`volocal-cli` now has an explicit `[[bin]]` in `Cargo.toml`, so the tauri-cli
bug cannot drop a second program from the installer unnoticed if one is
ever added. README (both halves) lose the TUI line; `docs/cli-look-plan.md`
points here.

Verified: `cargo test` 325 + 24, clippy and fmt clean, `npm run build`,
`npm test` (339), `i18n:check`, `docs-check`; `Cargo.lock` no longer holds
`ratatui` or `rodio`.

`src-tauri/Cargo.lock`, `src-tauri/src/bin/volocal-cli/common.rs`,
