# 2026-10-02

### 2026-10-02 — The page can be served from our own server, and Vercel keeps serving it until the address moves

The owner is moving the company's sites off Vercel onto `znackarna-server2`,
which runs Next.js applications behind Caddy and nothing else: it installs the
packages, runs `next build` and starts `next start`. The page has no build step,
so it needed something for that server to start.

**What was added.** `site-server/`, a Next.js application of one route handler
that reads `docs/site` from disk on every request. Nothing in `docs/site`
changed and nothing is copied out of it. It does what `site.yml` does on the way
to Vercel:

- serves the same files `site.yml` copies into `_site`, and nothing else in
  `docs/site` (`translate.mjs`, `en.json`, `bundle.py` and the rest answer 404);
- makes the English page with `translate.mjs`, once per process;
- writes the latest release into *Verze* and *Version*, asking GitHub's API
  every ten minutes. `site.yml` redeploys when a release is published, and the
  server hears nothing about releases — a release is published by hand, hours
  after the commit that carries its number, so a number read only at build time
  would stay one release behind;
- refuses to build when `site.yml` would have refused to deploy: a sentence with
  no English, or anything but two version mentions in either page. A failed build
  on that server leaves the previous version running, which is what a failed
  `site.yml` job does on Vercel.

`/en/` stays `/en/` (`skipTrailingSlashRedirect`), because that is the address in
the page's canonical and hreflang links. Files are answered with Vercel's own
default, `public, max-age=0, must-revalidate`, and an ETag, so a returning reader
gets a 304.

**What it does not do.** Vercel's Web Analytics script, `/_vercel/insights/script.js`,
exists only on Vercel; on the server it answers 404 and nothing is counted.
Choosing a replacement is the owner's decision, not part of this change.

**Why not `output: 'export'`.** That writes static files, and `next start` refuses
to run with it; the server starts every application with `next start`. **Why not
`public/`.** The server runs `next build` directly, without the package's own
build script, so nothing would copy `docs/site` into it.

Vercel is untouched: `site.yml` deploys from `docs/site` as before and never looks
at `site-server/`.

**Verified** with `next dev` (no production build on the shared machine): `/`,
`/index.html`, `/en/`, `/en` and `/en/index.html` answer 200 with *Verze 1.2.26*
and *Version 1.2.26*, the latest release; the English page asks for
`../brand.css`; stylesheets, scripts, fonts with their licences, both cards,
`robots.txt` and `sitemap.xml` answer with their types; the tools in `docs/site`,
`README.md`, an unknown path and `/fonts/%2e%2e/en.json` answer 404; a repeated
request with the ETag gets 304. The build check passed on the page as it is, and
refused a copy of it with one translation removed, with `translate.mjs`'s own
message.

### 2026-10-02 — volocal.app moved to the server; visits counted by Umami instead of Vercel Analytics

At 8:40 `volocal.app` and `www.volocal.app` were pointed at `znackarna-server2` (DNS at Subreg) and
the server deploys `main` through `site-server/` on every push (a GitHub webhook; a failed build keeps
the previous version running). Every file the page links to was compared with Vercel before the switch
and matched. **`site.yml` is disabled** in GitHub Actions – nothing deploys to Vercel any more; the
project there stays only as a fallback for a week and is then deleted. The version on the page comes
from the latest GitHub release, which the server asks for every ten minutes, so publishing a release
needs no deploy.

Vercel Analytics exists only on Vercel, so its script is replaced in `docs/site/index.html` by the
company's own **Umami** (`https://stats.znackarna.dev`, website „Volocal“): no cookies, nothing stored
in the browser, counted only on `volocal.app` and `www.volocal.app` (`data-domains`). The English page
gets the same tag through `translate.mjs`.
