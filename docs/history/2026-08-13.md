### 2026-08-13 — Two clicks on *Zálohovat teď* in one second reported a broken archive

Found by pressing the button quickly in the running application:

```
output file already exists: Error code 1: SQL error or missing database
```

Nothing was broken. The stamp in a backup's name is accurate to the second —
`volocal-2026-08-13-004512.db` — and the button re-enables the moment the first
copy is written, so a second click inside the same second aims at a name that is
already taken. `VACUUM INTO` refuses to overwrite, and its refusal arrived on
screen wearing the words *SQL error or missing database*, which is the last
sentence anybody should read about an archive that is perfectly fine.

Fixed where the name is made, not where the copy is written: if a file for this
second is already there, it is the copy this call would have made, and it is
returned. What was asked for is a backup of now, and there is one.

Two fixes deliberately not made:

- **Widening the stamp.** `backup_stamp` parses exactly `0000-00-00-000000`,
  `list_backups` orders by that text, and the rotation reads the day out of it.
  Every backup already written on every machine is in that shape.
- **Overwriting.** `back_up`'s own comment says it refuses to clobber so that a
  timestamped name can never land on an older copy. That is worth keeping, and
  this case is the one time the name is not an older copy's.

- Files: `src-tauri/src/db.rs`.
- Verified: a test that calls `back_up_and_rotate` twice in a row and asserts
  both return the same path and that one file exists rather than an error; plus
  `cargo fmt`, `clippy -D warnings`, `cargo test` (176 passed, 2 ignored).

### 2026-08-13 — Correcting entry: the caveat belongs to saving, not to loading

The entry above records the import note as his two sentences, the second of them
*Zvukové soubory nejsou součástí zálohy.* He moved it, and the move is better
than the wording was.

The two notes are now:

> **Uložit kopii archivu…** — Uloží jen texty bez zdrojové nahrávky.
>
> **Načíst archiv ze souboru…** — Načtený archiv nahradí ten současný.

What the archive does not contain is a fact about the copy being *written*, and
saying it there is saying it to the person who can still do something about it —
they are standing at a save dialog, and if they wanted the audio too they now
know to copy it themselves. Said at the load button it is a complaint arriving
too late, about a file somebody else made on a machine that may no longer exist.

And it leaves the destructive act with one sentence and one verb: *nahradí*.

Worth keeping as the rule behind both: a warning goes where somebody can still
act on it, not where it is merely true.

### 2026-08-13 — The security document was three days behind its own code

Asked whether the hardening plan written on 10 August is still needed. Checking
its ten packages against the repository answered both that question and a worse
one.

Eight are done and two are most of the way there. The repository has an English
README beside the Czech one, a root `LICENSE`, contribution rules and templates,
`main` protected behind a pull request and two required checks; `download.rs`
hashes what it downloads; `assetProtocol.scope` is `[]` and one file is opened at
a time; `main.rs` went from 2 420 lines to 1 299 and `transcription.rs` became
five modules; `CLAUDE.md` is 138 lines with the change log in this folder. What
is left of packages 4 and 6 — more component tests, and `Detail.tsx` still at
2 833 lines — is improvement rather than repair, and is nobody's emergency.

Package 3, the one that was finished first, is the one that had rotted. The
entry on 10 August ends *the security documentation says what the code does*,
and it did, that day. Then components got pinned with digests and it stopped
being true, and #67 went through the file on 12 August taking version numbers
out without reading what surrounded them. `SECURITY.md` was still telling
readers:

- that `EXPECTED_HASHES` is **empty** and *nothing is compared, for any
  component* — a constant that no longer exists, replaced by
  `components.json`, where fifteen of sixteen entries carry a digest read from
  the publisher;
- that five entries are found by a regular expression over live GitHub releases
  and `yt-dlp` points at `releases/latest/download/` — no address in the
  catalogue contains `latest`, and a test fails the build if one ever does. The
  pattern moved to `scripts/update-components.mjs`, which proposes a version in
  a pull request somebody reads;
- that every installation records `verified: false`.

A security document that understates what the code does is not the harmless
direction of wrong. It is read by whoever is deciding whether to trust the
program, and by whoever is deciding what still needs building — and this one was
describing an unsolved problem that had been solved.

Rewritten in both halves, saying the same thing in each: fixed addresses,
digests read from the publisher and never computed here, and the one component
that has none. `model-hlasy` sits in a release uploaded before GitHub computed
asset digests, so it installs `verified: false` and the document says so by
name, along with the test that keeps it the only one. The advice *let the first
run happen on a network you trust* stayed, narrowed to the component it is still
about.

Kept as they were, because they are accurate: the CSP paragraph, the asset scope
paragraph, the unsigned installer, and the sentence saying the verification
record is not shown anywhere in the interface.

The plan itself is now `docs/hardening-plan-2026-08-10.md`, unchanged below a
header saying what it achieved. It describes Slobot 0.9.0 and correcting it
would only hide what was believed on the day it was written.
