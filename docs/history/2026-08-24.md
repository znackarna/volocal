# 2026-08-24

### 2026-08-24 — The page comes back into the repository

It was moved to a branch of its own on 20 August, and the reason was one thing:
`release.ps1` refuses a working tree with uncommitted changes in it, so a
half-finished paragraph on the page blocked a release three times in one day.

**That is the release script's rule, not a reason to split a repository.** The
fix is to commit page work like any other work, and to look at `git status`
before publishing — which is what the split was standing in for.

What the split cost, in four days: the branch went fourteen commits ahead and
four behind, and the page reads `brandArt.ts` and `Brand.tsx` from the
application, which on a branch means keeping up by hand. The owner noticed the
two branches on GitHub and asked why.

`docs/site/` is back on `main`, brought by a merge rather than a copy so the
fourteen commits keep their history. `site.yml` triggers on `main` now.
`docs/site.md`, which existed to say where the page had gone, is gone with it.

Both branches had written into the same day files, and neither entry is a
correction of the other, so both are kept — the same resolution as 20 August,
when the menu and the summary landed together.
