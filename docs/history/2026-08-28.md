# 2026-08-28

### 2026-08-28 — The two failures worth logging were the two not being logged

Asked whether the log is any use for finding a fault. The honest answer was
mostly no, and the reason is specific rather than general: of sixty-eight
`note!` calls, thirty-seven are in `main.rs`, so the record is dense around
startup, the archive and the window's plumbing, and thin to nothing everywhere
else. Downloads have one line. The library has one.

**But the gap that mattered was not thinness.** Two whole classes of failure
were leaving no trace at all:

**A panic in Rust.** There was no `panic::set_hook`, so a panic went to stderr —
which `#![windows_subsystem = "windows"]` gives nowhere to go. The single event
most worth having was the one being dropped. Somebody reporting that Volocal
"just closed" handed over a log with nothing in it around the moment it closed.

**A crash in the window.** `ErrorBoundary` already assembled the message, the
stack and React's component stack, and showed them on screen. That was the end
of it. Half of this application is in the window and none of its failures were
being kept — including both faults the owner found himself this week, the
flashing refusal on `Výkon` and the folder that could not be made, which are
both in React and would have left the log silent.

The hook goes in as the first statement of `main`, before the instance guard and
before Tauri, so anything below it is covered; the previous hook still runs, so
`tauri dev` prints exactly what it printed. It names the thread, because a panic
in a worker leaves the window standing and one on the main thread does not — the
person reporting it is describing two different faults.

`note_crash` takes the text the boundary had already built. It is capped at
4 000 characters from the top, because a component stack can run to hundreds of
lines and the log has a 512 kB ceiling that starts the file over — one crash must
not push out everything that led to it. The call is not awaited and every
failure is swallowed: the window is already broken, the backend may be why, and
a boundary that throws while handling a throw takes the crash screen down with
it and leaves the white window it exists to prevent.

Verified by test on both sides. `diagnostics::a_panic_reaches_the_log_file`
installs the hook, raises a panic through `catch_unwind` and reads the file
back — what was said, where, and by which thread. `src/ErrorBoundary.test.tsx`
is new: the crash reaches the log with its component stack, the crash screen
still appears, a thrown string with no stack is still sent, and a rejected
`noteCrash` does not take the screen down. Remove the one line that sends it and
two of the four fail.

245 Rust tests, 168 frontend tests, clippy and fmt clean.

**What is deliberately not done:** the thinness itself. Adding `note!` calls
across downloads, transcription and the library is a different job, and guessing
at which lines would have helped is how a log becomes noise nobody reads.

`src-tauri/src/commands/settings.rs`, `src/ErrorBoundary.tsx`, `src/api.ts`,
`src/ErrorBoundary.test.tsx`.
